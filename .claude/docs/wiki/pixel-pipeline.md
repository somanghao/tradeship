# 토픽: 픽셀 에셋 파이프라인

> `js/pixel.js` + `js/sprites/*` — 모든 그림을 **코드로 생성**하는 공통 기반. 팔레트·드로잉 DSL·베이크 캐시·자동 외곽선. (2026-08-08 구축)

## 왜 이렇게 만들었나

이미지 생성 도구가 없는 환경이라 그림을 코드로 그려야 했다. 사용자 기준은 **"2D나 픽셀 형태로, 싸구려같지만 않게"** — 고퀄 일러스트가 아니라 조악해 보이지 않을 정도.

또 하나의 요구: **"이미지 디자인은 한곳에 모아두고 그걸 가져다 쓰면 되잖아."**
→ 에셋 생성은 `js/sprites/` 안에 가두고, 바깥에는 `xxxSprite(key, opts) → canvas` 팩토리만 노출한다.
나중에 실제 렌더링 PNG로 교체해도 호출부는 그대로다.

## 왜 문자열 픽셀맵이 아니라 좌표 DSL인가

처음엔 `'....##..'` 같은 문자맵을 고려했으나 폐기:

| 문자맵 | 좌표 DSL (`G` 클래스) |
|---|---|
| 행 길이가 1칸만 어긋나도 스프라이트가 깨지는데 눈으로 못 찾는다 | 좌표 계산이라 어긋날 여지가 없다 |
| 파츠 재사용 불가 (모자만 바꾸려면 전체 재작성) | 파츠 함수 조합으로 변주 |
| 색 교체 불가 (문자↔색 매핑을 새로 만들어야) | 팔레트 인자로 스왑 |
| 48×40 하나 짜는 데도 오래 걸림 | 형태를 수식으로 기술 가능 (선체 곡선 등) |

```js
g.px(x,y,c)  g.r(x,y,w,h,c)  g.h(y,x0,x1,c)  g.v(x,y0,y1,c)
g.line(x0,y0,x1,y1,c)        // 브레젠험
g.ellipse(cx,cy,rx,ry,c)     // 스캔라인 채우기
g.poly([[x,y],...],c)        // 스캔라인 채우기
g.box(x,y,w,h,c)
```

## 싸구려로 안 보이게 하는 3가지 규칙

조악해 보이는 원인은 대부분 셋 중 하나다.

1. **단색 면** → 색군마다 `D`(그림자)/`M`(기본)/`L`(하이라이트) 3톤을 `PAL`에 미리 정의하고
   **그 표에서만** 색을 고른다. 임의 색을 즉석에서 쓰지 않는다.
2. **팔레트 난잡** → 아웃라인은 순검정(`#000`)이 아니라 보라기 섞인 먹색(`PAL.out = #17121c`).
   순검정은 화면에서 구멍처럼 보인다.
3. **외곽선 두께 불균일** → 손으로 두르지 말고 `outline()`으로 후처리 생성.

## outline() — 자동 외곽선 (핵심)

```js
outline(ctx, w, h, col = PAL.out)
```
불투명 픽셀에 인접한 **빈** 픽셀을 1px로 채운다. 실루엣을 손으로 두를 필요가 없고 두께가 항상 균일하다.

**함정 (실제로 당함):** 이건 "빈 픽셀"을 칠하므로, 캔버스에 **흩뿌려진 점**이 있으면 그 점 하나하나에 테두리가 생긴다. 지도 텍스처를 육지 마스크 없이 전체에 뿌렸다가 바다 전체가 격자무늬로 망가졌다. → [map-terrain.md](map-terrain.md)

**전제:** 스프라이트 가장자리에 최소 1px 여백을 남길 것. 꽉 채우면 외곽선이 그려질 자리가 없다.

## bake() — 스프라이트 캐시

```js
bake(key, w, h, (g, ctx) => { ...그리기...; outline(ctx, w, h); })  // → HTMLCanvasElement
```
draw 함수를 **1배 오프스크린 캔버스**에 한 번만 그려 캐시한다(확대는 `blit` 시점에 별도로 일어나므로, 같은 스프라이트를 여러 배율로 써도 원본은 하나다). key가 같으면 이미 만든 캔버스를 그대로 돌려준다. 그래서 **씬의 draw()가 매 프레임 `unitSprite('sailor','idle')`을 호출해도 비용이 0**이다. 호출부가 캐시를 신경 쓸 필요가 없다.

key에는 외형을 바꾸는 모든 인자를 넣어야 한다. 예: `ship:${hull}:${tint}:${flag}:${furl}:${firing}:${damaged}`

## 조립 패턴 — 베이스 + 파츠 + 팔레트 스왑

병종 9종을 각각 그리지 않는다. **베이스 바디 1개**에 파츠를 얹고 색만 바꾼다.

```
drawArms(뒤팔) → drawLegs → drawTorso → ARMOR[x] → drawHead
  → HEADGEAR[x] → drawFrontArm → WEAPONS[x] → outline()
```
- `HEADGEAR`: none / bandana / tricorne / plumehat / morion / turban / hood
- `WEAPONS`: cutlass / scimitar / pike / musket / crossbow / swordshield / torch
- `ARMOR`: none / cuirass / buffcoat / bandolier
- `SCHEMES`: navy / crimson / forest / ink / sand / plum (+ 피부톤 light/dark)

**이 방식의 이점:** 병종을 늘려도 비례와 실루엣이 어긋나지 않는다. 새 병종 = `UNITS`에 조합 한 줄.

**그리는 순서가 곧 z축**이다. 뒤쪽 팔을 먼저, 무기를 마지막에. 순서를 바꾸면 무기가 손 뒤로 들어간다.
(총병은 예외 — 무기가 손을 덮으므로 `musket()` 안에서 앞손을 다시 얹는다)

## 포즈

`poseOf(name)`이 오프셋 몇 개만 바꾼다. 프레임을 따로 그리지 않는다.

| pose | lean | armY | armX | legSpread | wSwing |
|---|---|---|---|---|---|
| idle | 0 | 0 | 0 | 0 | 0 |
| attack | 2 | -4 | 3 | 2 | -20 (무기 내려치기 / 총구 화염) |
| hit | -2 | 1 | -2 | 0 | 25 |

## 규격

| 스프라이트 | 크기 | 기준선 |
|---|---|---|
| 캐릭터 | 48×48 | 발바닥 `CHAR_FOOT = 45` |
| 선박 측면 | 176×128 | 수면 `WATERLINE = 104` |
| 선박 탑다운 | 28×28 | 위쪽이 선수 |
| 교역품 아이콘 | 16×16 | — |
| 배경/씬 | 400×225 | `VW`/`VH` (게임 논리 해상도) |

배치할 때 이 기준선을 쓴다. 예: 캐릭터를 갑판에 세우려면 `y = 갑판절대y - CHAR_FOOT`.
→ [battle-system.md](battle-system.md)의 백병전 배치

## 선체 — 수식으로 그리기

선박은 좌표를 찍지 않고 **현호(sheer)/용골(keel) 곡선 함수**로 생성한다.

```js
sheerAt(H,t)  // 중앙이 낮고 양 끝이 올라가는 곡선 (선미 쪽이 더 높다)
keelAt(H,t)   // 중앙이 가장 깊은 배 바닥
```
컬럼별로 top~bottom을 세로선으로 채우고, 그 위에 현측 띠·포문·선루·돛대를 얹는다.
덕분에 `HULLS`의 비례값(`len/deck/depth/sheerAft/...`)만 바꾸면 새 선종이 나온다.

**가로 판재 결**은 현호를 따라 흐르게 그려야 한다. 수평 직선으로 그으면 선체가 휘어 보이지 않는다.
