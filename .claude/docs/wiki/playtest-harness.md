# 플레이테스트 하네스 — 사람처럼 눌러 보는 장치

브라우저를 실제로 띄우고 **사람 손 속도로 클릭해** 게임을 굴리는 도구. 단위 테스트가 못 잡는 것
— 첫 화면이 검다, 안내가 스크롤 밖에 있다, 조사가 `을(를)`로 남아 있다, 좁은 창에서 단추가
패널 밖으로 나간다 — 은 눌러 봐야 나온다.
검증 도구 전체 목록은 [dev-workflow.md](dev-workflow.md), 실제로 눌러 본 기록은 [playtest-log.md](playtest-log.md).

## §0. 넷이 있다 — 배치 · 관전 · 아홉 바다 · 보강

앞의 둘이 **도구**고, 뒤의 셋은 그 도구로 짠 **회차 러너**다(`tools/playtest-live/`).

| 러너 | 무엇을 재나 | 창 |
|---|---|---|
| `nine-seas.mjs` | 아홉 바다를 **동시에** 굴려 A 기동 · B 항구 · C 항해와 사건(권역당 14구간) | 9 (3×3) |
| `ocean-season.mjs` | **원양 항로**와 **계절 전환** — 권역 안 항해로는 구조적으로 안 나온다 | 4 (2×2) |
| `payday-inland.mjs` | **급여일·체불**과 **육로 사건** — 30일·0.12 확률이라 짧은 회차로는 안 걸린다 | 4 (2×2) |

셋 다 **2번 모니터에만** 창을 놓고(사용자 지침), 사건 분류표 `event-signs.mjs`를 함께 쓴다.
**두 러너를 동시에 띄우지 않는다** — 같은 자리를 쓴다.
결과는 `.playtest/nine-seas/`(계획 `TESTPLAN.md` · 판정 `RESULTS.md` · 발견 `FINDINGS.md`),
진행판은 `http://localhost:8891/.playtest/nine-seas/`가 `live.json`을 폴링해 보여 준다.

| | `tools/playtest.mjs` (먼저 있던 것) | `tools/playtest-live/` (관전용) |
|---|---|---|
| 모양 | **한 스크립트로 처음부터 끝까지** — `open()` → `click`·`buy`·`sail`·`sellAll` → `close()` | 창을 띄워 두고 **명령마다 붙었다 뗀다** |
| 브라우저 | 스크립트가 열고 닫는다(`headed`·`slow` 옵션) | 계속 살아 있다 — 게임 상태가 유지된다 |
| 쓸 때 | 회귀 검증·스모크(`node tools/playtest.mjs --smoke`) | **사람이 옆에서 보며** 한 수씩 두고 판단할 때 |
| 커서 | 없다(DOM 클릭) | **반투명 원**과 클릭 링을 페이지 안에 그려 눈으로 따라갈 수 있다 |

**정해진 절차를 돌릴 것이면 `playtest.mjs`를 먼저 본다.** 이 문서의 `playtest-live`는
"다음에 뭘 누를지 화면을 보고 정하는" 탐색용이다.

## §2. 굴리는 순서

```bash
python serve.py 8891                     # no-store 서버 (필수 — §3 캐시)
node tools/playtest-live/launch.mjs           # 창을 띄워 둔다(백그라운드). 이 프로세스가 죽으면 창도 죽는다
node tools/playtest-live/play.mjs shot        # 지금 화면 + 누를 수 있는 것 목록(접어서)
node tools/playtest-live/play.mjs ui 곡물     # 그 글자가 든 것만 전부 · `--full`은 접지 않고 전부
node tools/playtest-live/play.mjs click "곡물 · 사기"
node tools/playtest-live/play.mjs start "guangzhou&crew=9"   # 그 항구에서 새로 시작(타이틀 문구까지 찍는다)
node tools/playtest-live/play.mjs sail 마카오                # 항구→지도→그 항로, 도착이나 조우까지 지켜본다
node tools/playtest-live/play.mjs clickxy 375 242 3     # 좌표로 3번
node tools/playtest-live/play.mjs eval "__game.state.gold"
```

캡쳐는 `tools/playtest-live/.out/shot.png`에 덮어쓴다. `play.mjs`는 매번 새로 붙었다 떼므로
**게임 상태는 창에 그대로 남는다** — 한 판을 여러 명령으로 이어서 굴릴 수 있다.

**같은 글자가 여럿이면 문맥이 붙는다.** 시장은 `사기`가 스무 줄이고 술집은 `태운다`가 넷이라
글자만으로는 고를 수 없다 → `ui`가 행·카드의 **이름칸 첫 줄**을 앞에 얹어 `곡물 · 사기` ·
`허(許)씨 패 · 태운다 (−21닢)`로 준다. 금액만 다른 형제도 같은 단추로 보고 문맥을 붙인다.
그래도 여럿이 걸리면 `click`이 `AMBIGUOUS`로 골라 누를 문자열을 알려 준다.

**사람 속도**란: 커서를 ease-in-out으로 12~22ms/스텝씩 밀고 → 220~420ms 겨냥하며 멈칫 →
60~120ms 누르고 → **0.9~1.6초 결과를 본다.** 포격전은 한 턴이 약 2초라 이보다 빠르면
`disabled`에 막힌다([dev-workflow.md](dev-workflow.md)).

### 화면 밖에서 시작하기 (권역별 시작 시험)

정식 게임은 늘 베네치아에서 시작한다. 다른 바다는 `start`가 `?start=`로 새로 열고
에셋 베이크를 기다렸다가 타이틀 문구를 찍고 닫는다 — 뒤에 `&gold=`·`&crew=`·`&ship=`을 붙일 수 있다.

```bash
node tools/playtest-live/play.mjs start "guangzhou&crew=9"
# 아홉 바다 교역기 — 광저우 — 낡은 바사 한 척과 금화 200닢 · 선원 9명
```

**도시 id는 이름과 다르다** — 캄바트는 `cambay`, 베네치아는 `venezia`. 틀린 id는 조용히
베네치아로 열리므로 `start`가 `WRONG_START`로 잡아 준다(§3). 시작지는 항로가 셋 이상인
항구를 고른다 — 막다른 주머니(사카이·마포·카이로·이스파한·세부)는 첫 항해비가 시작 자금에 육박한다.
상태를 손으로 바꾸려면 동적 import가 **같은 모듈 인스턴스**를 준다(URL이 같으면 캐시된다):
`eval "(async()=>{const s=await import('./js/state.js'); s.state.gold=5000; return s.state.gold})()"`.

## §3. 이 하네스를 만들며 밟은 함정

- **OS 마우스는 페이지에 닿지 않는다.** `SetCursorPos`/`mouse_event`로 커서를 옮기면 좌표는 바뀌는데
  (`Cursor::Position`으로 확인됨) 페이지에 `mousemove`가 오지 않고 `WindowFromPoint`가 늘
  `Program Manager`를 돌려준다. 그래서 **입력은 CDP로 넣고 커서는 페이지 안에 그린다**
  (`play.mjs`의 `__cur`/`__ring` 오버레이). 사용자가 눈으로 따라갈 수 있으면 목적은 같다.
- **창을 항상-위로 점유하지 않는다.** 오버레이 커서는 페이지 안에서 그리므로 z-order와 무관하다.
  창이 다른 앱 뒤에 숨어 "아무것도 안 움직이는" 것처럼 보일 때만 `raise-window.ps1`로 한 번 올린다.
- **첫 로드는 몇 초 검다**(에셋 베이크). 2초 뒤 캡쳐하면 빈 화면이 찍힌다 — 6~8초 기다린다.
- **긴 목록에서 좌표로 연속 클릭하지 마라.** 매매하면 배지·줄바꿈이 바뀌며 행 높이가 달라져
  다음 클릭이 다른 품목을 누른다. 문맥이 붙은 `click "곡물 · 사기"`를 쓰거나 매번 좌표를 다시 잰다.
- **누를 수 있는 것을 태그로만 찾으면 놓친다.** 지도의 항로는 `span.rn`에 리스너를 달아 두어
  `button`도 `[onclick]`도 아니다 — 그래서 `ui`는 **`cursor:pointer`**까지 후보로 본다.
  대신 배지·수치 조각이 함께 걸리므로 **단추가 아닌 자식은 그 행에 흡수**한다(행 중앙 클릭이 먹는다).
- **라벨에 변하는 값을 넣지 마라.** 이름칸을 통째로 쓰면 `곡물 수요 11/11 · 사기`가 되고, 시세가 움직여
  순위 배지가 바뀌면 어제 쓰던 클릭 문자열이 죽는다 → **이름칸의 첫 줄만** 쓴다.
- **없는 도시 id는 조용히 베네치아가 된다.** `applyDebugStart`가 콘솔 경고만 남기고 시작 항구를 그대로 두므로,
  `khambhat`(실제는 `cambay`)로 열고도 인도양을 본다고 착각한다 — 실제로 한 번 속았다. `start`가 대조해 잡는다.
- **사건은 항해 *도중* 모달로 끊는다.** 도착만 기다리면(`state.at` 변화·`scene==='battle'`) 조우 선택 화면에서
  영원히 안 끝나고, 그 상태로 다음 명령을 넣으면 "항로가 없다"고 죽는다 → 보이는 모달도 함께 본다.
  `sail`은 **시작할 때도** 검사해 `PENDING_MODAL: 돛이 보인다 — 먼저 이 화면을 처리한다`로 알린다.
- **`.modal-box`를 그냥 잡으면 항해일지가 걸린다.** 그것은 `display:none`으로 **늘 DOM에 있다** —
  그래서 "모달 있음"이 항상 참이 되고 첫 줄이 빈 문자열이라 조우를 영원히 놓친다.
  `blockingModal()`이 **보이는 것만**(display·visibility·opacity) 센다.
- **항해일지는 최신이 앞이다**(`state.log[0]`). `slice(-3)`은 1일차 로그를 보여 준다.
  ★ 같은 이유로 **`slice(이전 길이)`로 "새로 붙은 줄"을 읽으면 안 된다** — `pushLog`가 unshift라
  늘 *가장 오래된* 줄이 잡힌다(60줄 넘으면 뒤를 pop). 항해 전 **머리줄을 기억해 두고 그 줄을 만날
  때까지 앞에서 걷는다**(`nine-seas.mjs: logHead/logSince`). 이 하나로 아홉 바다가 전부
  "해상 사건 0건"이라는 거짓 결과를 냈다.
- **원양 항로는 캔버스 클릭으로 못 간다.** 지도에 **선으로 안 그려지기 때문**이다 — 권역마다 좌표계가
  따로라 그을 좌표가 없다(`map.js: oceanRows`). 사람은 사이드패널 `.route-row` 카드를 눌러 간다.
  `sail(id, {name})`에 도시 한글명을 주면 좌표가 없을 때 그 카드로 간다. 고치기 전까지
  **하네스는 원양 항로를 한 번도 밟아 본 적이 없었다**(여덟 번 전부 "미도착·1일차 그대로").
- **급여일 모달은 `closable:false`라 처리하지 않으면 다음 출항이 통째로 막힌다.** 원양은 한 구간이
  30~48일이라 **항해 한 번에 급여일이 지나간다** — 첫 원양 회차가 한두 번 왕복하고 37~49일에 갇혔다.
- **★ 화면이 검을 때 하네스가 원인을 말해 준다.** `open()`이 `window.__game`을 못 찾으면
  `TimeoutError` 대신 **콘솔에 남은 자국을 함께** 던진다 —
  `window.__game이 안 뜬다 — 게임 코드가 죽었을 수 있다: SyntaxError: Identifier 'x' has already been declared`.
  모듈 하나가 깨지면 스크립트가 한 줄도 안 돌아 화면이 검게 남는데(`gotchas.md` 6번), 전에는
  "브라우저가 안 뜬다"와 구분할 수 없었다.
- **★ 러너가 남긴 크롬이 쌓인다.** 러너를 중간에 죽이면 playwright가 띄운 크롬이 안 닫혀
  실측에서 **235개**까지 갔고, 그때부터 새 브라우저가 안 뜬다. 회차 사이에 확인하고 정리한다 —
  사용자의 크롬을 죽이지 않게 `--remote-debugging-*`·`--headless`가 붙은 것만 고른다.
- **★ `'출항'`을 글자로 찾으면 안 된다 — 제목 화면이 DOM에 남아 있다.** `#title-screen`은 닫혀도
  제거되지 않아 그 안의 '출항하기'가 먼저 잡힌다. 누르면 아무 일도 안 나는데 `click`은 **true**를
  돌려주므로, 씬은 그대로인 채 "지도로 못 갔다"만 반복된다. 항구의 출항 단추는 `.btn-sail`이다 —
  **그것을 직접 누른다.** 이것 하나로 한 배치의 미도착이 **68건**까지 갔고, 그 사이 나는
  자금·급여일·전투 재개를 차례로 의심하며 엉뚱한 곳을 고쳤다.
- **급여일 모달은 항구에 있을 때 뜬다 — '항해 중'만 보고 넘기면 그 뒤 모든 출항이 막힌다.**
  `closable:false`라 치우기 전에는 아무것도 눌리지 않는다. 매 구간 앞에서 **막는 모달을 먼저 치운다.**
- **팔지 않으면 자금이 마르고, 자금이 마르면 출항이 막힌다.** 매수 케이스가 화물칸을 가득 채우면
  금고가 바닥나는데(12,000 → 114닢) 러너가 한 번도 팔지 않으면 항해비를 못 댄다. **사고 판다.**
- **화면 셀렉터는 실제 DOM에서 확인하고 쓴다.** 술집은 `#tavern-panel .tav-card`, 조선소는
  `#yard-panel .yard-ship`이다. 짐작으로 `.crew-row`·`.ship-row`를 쓰면 화면에 무리 셋·배 93척이
  떠 있는데도 **"목록 0줄"** FAIL이 나온다.
- **`favicon.ico` 404를 콘솔 오류로 세지 마라.** `index.html`에 아이콘이 없어 브라우저가 제 발로
  부르고 404를 받는다 — 이것 하나로 아홉 권역 TC-01이 전부 FAIL이 됐다.
- **`state.payroll`의 필드는 `{due, arrears, nextDue, lastDay}`다.** 없는 이름(`accrued`)을 보면
  삯이 날마다 쌓이는데도 실패로 적힌다.
- **목적지를 무작위로만 고르면 가장 가까운 둘을 왕복만 한다.** 부산포~내이포(육로 1일)를 열 번 왕복해
  14구간을 뛰고도 11일이었다 — 짧은 구간은 판정도 한 장씩(`rollsLeft = ceil(days/8)`)이라
  사건 표본이 안 모인다. **가 본 적 없는 항구를 우선**하고 육로는 횟수를 정해 따로 확보한다.
- **확률이 낮은 사건은 "안 났다"를 결함으로 적지 마라.** `INLAND_ODDS`가 0.12라 육로를 두 번 타면
  77%가 무사통과다. 스물다섯 번을 타야 무사통과가 4%로 내려간다 — **표본을 설계하고 나서 판정한다.**
- **`python -m http.server`를 쓰면 안 된다.** 캐시가 섞여 낡은 .js가 물리고 화면이 통째로 검게 남는다.
- **시뮬은 한 판으로 판단하지 않는다.** `sim-trade.mjs`를 한 번 돌려 "이 커밋은 90항차 완주"라고
  결론 내릴 뻔했는데, 같은 커밋을 다시 돌리니 11항차에서 멈췄다. `sim-stat.mjs`로 20판을 본다.
- **곡선이 나쁘면 게임보다 *시뮬의 플레이 전략*을 먼저 의심하라.** 실제로 "선체 60% 미만이면 전액 수리"가
  누수 2pt/일짜리 시작배에 적용돼 하루 28닢을 태웠고, 그것만으로 20판 중 18판이 배를 못 샀다.
  게임은 멀쩡했다. → [playtest-log.md](playtest-log.md) §4-2

## §4. 무엇을 볼 것인가 (권역을 새로 열 때 훑는 순서)

1. **항구** — 시장 품목이 그 바다 것인가, 안내가 목록 위에 보이나, 배 그림이 갈아탄 배로 바뀌나
2. **술집** — 인물 이름이 권역을 따르나(중복 이름은 없나), 최소 인원 안내가 맞나
3. **조선소** — 그 권역 선종이 뜨나, 잠금 문구·조사·매각 확인창
4. **지도** — 축척, 항로 목록(일수·비용·위험), 원양 항로, 감당 못 하는 항로 표시(`.rd.short`)
5. **항해** — 사건이 나나(표류물·해적·노상강도), 로그 문장의 조사
6. **전투** — 적의 이름·깃발·선종이 그 바다 것인가, 도주·임검 처리
7. **로그** — `을(를)`·`이(가)`·`(으)로`가 남아 있지 않나 (`js/josa.js`)
