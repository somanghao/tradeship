# 토픽: 지중해 지형 생성

> `js/sprites/scene.js`의 `SEA_SPANS` / `ISLES` / `buildLandMap()` / `mapSprite()` — 400×225 지중해 지도. **세 번 갈아엎고 확정된 구조**라 접근법을 바꾸기 전에 이 문서를 읽을 것. (2026-08-08)

## 폐기한 두 가지 접근 (같은 실수 반복 금지)

### 1차: 육지 폴리곤 나열 — 실패

이베리아·이탈리아·발칸·아나톨리아·아프리카를 각각 폴리곤으로 정의했다. 결과:

- **이탈리아 반도가 1px 사선**이 됐다. 티레니아 해안선과 아드리아 해안선 좌표가 대각선으로 붙어버려 반도 폭이 남지 않았다.
- **그리스가 통째로 바다에 잠겼다.** 이오니아해 구간 `[37,43]`과 에게해 구간 `[45,59]`가 사실상 이어져 반도 자리에 육지가 0칸.
- 폴리곤 좌표만 봐서는 이런 사고를 **미리 알 수 없다.** 렌더해서 눈으로 봐야 발견된다.

### 2차: 수역 폴리곤 파내기 — 개선됐으나 부족

지중해는 닫힌 내해이므로 "전체를 육지로 채우고 바다를 `destination-out`으로 파낸다"로 전환. 형태는 나아졌지만 여전히 폴리곤 정점으로 반도를 통제해야 해서 정밀도가 안 나왔다.

### 3차(확정): 행별 수역 구간 격자

100×56 저해상 격자에 **행마다 바다인 x 구간**을 적는다. 이게 최종.

```js
const SEA_SPANS = {
  22: [[0,3], [11,30], [36,43], [47,60]],   // 대서양 / 서지중해 / 아드리아 / 에게
  //                    ^^^^^^^^^^^^^^ 사이의 44~46이 그리스 반도 육지
};
```

**왜 이게 나은가:** 반도는 "구간과 구간 사이의 틈"으로 표현된다. 육지 폭이 몇 칸인지 표를 보면서 바로 셀 수 있어서, 반도가 사라지는 사고가 원천적으로 생기지 않는다.

## 좌표계

| 격자 | 실제 지형 |
|---|---|
| x 0~99 | 대서양(0) → 레반트 내륙(99) |
| y 0~55 | 알프스 이북(0) → 사하라(55) |
| 확대 | ×4 → 400×224 (`GS = 4`) |

주요 랜드마크의 격자 좌표: 지브롤터 `(5,31)` / 보스포루스 `(60,12)` / 이탈리아 발끝 `(38,33)` / 튀니지 곶 `(42,38)` / 나일 삼각주 `(83,40)`

**좁은 물길은 반드시 행을 이어줘야 한다.** 인접 행의 구간이 x축에서 겹쳐야 물이 통한다.
- 흑해 y11 `[61,80]` → 보스포루스 y12 `[59,63]` → 마르마라 y13 `[56,62]` → 에게 y14 `[52,60]` (연쇄로 겹침)
- 지브롤터: y30 `[6,34]`+`[0,3]` → y31 `[0,34]` (통합되어 대서양과 연결)

## 업스케일 — 최근접 금지, 이중선형

4배 최근접 확대는 **대각 해안을 4px 톱니**로 만든다. 대신:

```js
v = bilinear(sea, x/GS - 0.5, y/GS - 0.5)   // 0..1 실수
land = (v + (noise-0.5)*0.22) < 0.5          // 임계값 + 약한 노이즈
```
- 보간으로 경계가 실수값이 되어 매끄럽게 떨어진다.
- `jitter` 노이즈(±0.11)를 섞어 해안선에 미세 요철을 준다. 없으면 자로 그은 느낌.
- 이후 **3×3 다수결 2패스**로 외딴 픽셀을 정리한다(과하게 돌리면 작은 반도가 깎이므로 2회 고정).

## 섬 — 확대 후에 찍는다

`ISLES`는 격자가 아니라 **최종 400×225 좌표**로 정의한다.

```js
[156,147,13,5]  // 시칠리아: [중심x, 중심y, 반경x, 반경y]
```
**격자에 넣으면 스무딩에 먹혀 사라진다.** 로도스(3×4)·몰타(2×2) 같은 작은 섬은 격자 1칸 미만이라 애초에 표현 불가.

시칠리아는 이탈리아 발끝과 붙지 않도록 좌표를 조정했다(메시나 해협 유지). 섬을 옮길 때 본토와의 간격을 확인할 것.

## 그리는 순서 (mapSprite)

순서가 어긋나면 화면이 망가진다. 특히 4번은 필수.

```
1. 육지 찍기 (land 불리언 → 가로 런 단위로 P.grnM)
2. 섬 타원
3. ★ 육지 마스크 확보 (getImageData) — isLand(x,y)
4. 지대 색조 (사막/관목/삼림)   ← isLand 안에서만
5. 내륙 얼룩 16000점            ← isLand 안에서만
6. 산맥                          ← isLand 안에서만
7. outline ×4 (백사장 → 천해 → seaL → 심해 경계)
8. destination-over 로 외해 그라데이션
9. 해류 결                       ← 육지 근처 제외
```

**4~6에서 `isLand` 검사를 빠뜨리면 대참사.** 실제로 한 번 당했다: 텍스처를 전체 캔버스에 뿌렸더니 7번 `outline()`이 바다에 흩뿌려진 점 하나하나에 테두리를 그려 화면 전체가 청록 격자무늬가 됐다. → [pixel-pipeline.md](pixel-pipeline.md)의 outline 함정

## 지대 경계 — 직선 금지

```js
desertY = (x) => 152 + sin(x*0.031)*7 + sin(x*0.011+2)*6;
scrubY  = (x) => 78  + sin(x*0.024+1)*12 + sin(x*0.009)*9;
```
`y > 152`처럼 상수로 자르면 화면을 가로지르는 **띠**로 보인다. sin 2개를 다른 주기로 겹쳐 흔들어야 자연스럽다. 아라비아 사막은 별도 조건(`x>352 && y>116+...`).

## 해안선 색 번짐

`outline()`을 색만 바꿔 4번 연속 호출하면 육지에서 바깥으로 4px 띠가 생긴다.

```
P.sandL(백사장) → #6fc4cc(초천해) → P.seaL → #2c6f8c
```
그 다음 `globalCompositeOperation = 'destination-over'`로 남은 빈 픽셀(외해)에 그라데이션을 깐다. 순서가 반대면 바다가 육지를 덮는다.

## 도시 배치

도시 좌표는 `js/data.js: CITIES`의 `x`/`y`(400×225 기준)에 있고 지형 파일과 분리돼 있다.
지형을 수정하면 도시가 육지 한복판이나 먼바다에 놓일 수 있으니 함께 확인할 것.
마커는 캔버스에 `arc()`로 그리므로(픽셀 스프라이트 아님) 지형과 별개로 항상 또렷하다.
