# 토픽: 지중해 지형 생성

> `js/sprites/scene.js`의 `SEA_SPANS` / `ISLES` / `buildLandMap()` / `mapSprite()` — 400×225 지중해 지도. **세 번 갈아엎고 확정된 구조**라 접근법을 바꾸기 전에 이 문서를 읽을 것. (2026-08-08)

## 폐기한 두 가지 접근 (같은 실수 반복 금지)

### 1차: 육지 폴리곤 나열 — 실패

이베리아·이탈리아·발칸·아나톨리아·아프리카를 각각 폴리곤으로 정의했다. 결과:

- **이탈리아 반도가 1px 사선**이 됐다. 티레니아 해안선과 아드리아 해안선 좌표가 대각선으로 붙어버려 반도 폭이 남지 않았다.
- **그리스가 통째로 바다에 잠겼다.** 이오니아해 구간 `[37,43]`과 에게해 구간 `[45,59]`가 사실상 이어져 반도 자리에 육지가 0칸.
- 폴리곤 좌표만 봐서는 이런 사고를 **미리 알 수 없다.** 렌더해서 눈으로 봐야 발견된다.

### 2차: 수역 폴리곤 파내기 — 개선됐으나 부족

지중해는 닫힌 내해이므로 "전체를 육지로 채우고 바다를 `destination-out`으로 파낸다"로 전환. 형태는 나아졌지만 여전히 폴리곤 정점으로 반도를 통제해야 해서 정밀도가 안 나왔다.

### 3차(확정): 행별 수역 구간 격자

100×56 저해상 격자에 **행마다 바다인 x 구간**을 적는다. 이게 최종.

```js
const SEA_SPANS = {
  22: [[0,3], [11,30], [36,43], [47,60]],   // 대서양 / 서지중해 / 아드리아 / 에게
  //                    ^^^^^^^^^^^^^^ 사이의 44~46이 그리스 반도 육지
};
```

**왜 이게 나은가:** 반도는 "구간과 구간 사이의 틈"으로 표현된다. 육지 폭이 몇 칸인지 표를 보면서 바로 셀 수 있어서, 반도가 사라지는 사고가 원천적으로 생기지 않는다.

## 좌표계

| 격자 | 실제 지형 |
|---|---|
| x 0~99 | 대서양(0) → 레반트 내륙(99) |
| y 0~55 | 알프스 이북(0) → 사하라(55) |
| 확대 | ×4 → 400×224 (`GS = 4`) |

주요 랜드마크의 격자 좌표: 지브롤터 `(5,31)` / 보스포루스 `(60,12)` / 이탈리아 발끝 `(38,33)` / 튀니지 곶 `(42,38)` / 나일 삼각주 `(83,40)`

**좁은 물길은 반드시 행을 이어줘야 한다.** 인접 행의 구간이 x축에서 겹쳐야 물이 통한다.
- 흑해 y11 `[61,80]` → 보스포루스 y12 `[59,63]` → 마르마라 y13 `[56,62]` → 에게 y14 `[52,60]` (연쇄로 겹침)
- 지브롤터: y30 `[6,34]`+`[0,3]` → y31 `[0,34]` (통합되어 대서양과 연결)

## 업스케일 — 최근접 금지, 이중선형

4배 최근접 확대는 **대각 해안을 4px 톱니**로 만든다. 대신:

```js
v = bilinear(sea, x/GS - 0.5, y/GS - 0.5)   // 0..1 실수
land = (v + (noise-0.5)*0.22) < 0.5          // 임계값 + 약한 노이즈
```
- 보간으로 경계가 실수값이 되어 매끄럽게 떨어진다.
- `jitter` 노이즈(±0.11)를 섞어 해안선에 미세 요철을 준다. 없으면 자로 그은 느낌.
- 이후 **3×3 다수결 2패스**로 외딴 픽셀을 정리한다(과하게 돌리면 작은 반도가 깎이므로 2회 고정).

## 섬 — 확대 후에 찍는다

`ISLES`는 격자가 아니라 **최종 400×225 좌표**로 정의한다.

```js
[156,147,13,5]  // 시칠리아: [중심x, 중심y, 반경x, 반경y]
```
**격자에 넣으면 스무딩에 먹혀 사라진다.** 로도스(3×4)·몰타(2×2) 같은 작은 섬은 격자 1칸 미만이라 애초에 표현 불가.

시칠리아는 이탈리아 발끝과 붙지 않도록 좌표를 조정했다(메시나 해협 유지). 섬을 옮길 때 본토와의 간격을 확인할 것.

### ⚠️ 섬끼리의 간격도 재라 — 눈으로는 안 보인다

몰타를 `[166,154,2,2]`로 두었더니 시칠리아(`[156,147,13,5]`, 남안 y=152)와 **경계 간격 0px(맞붙음)**이라 한 덩어리로 보였다.
지도 축척이 대략 **10km/px**이므로 실제 거리 90km면 **9px**은 띄워야 한다 → `[169,161,2,2]`로 옮겼다.

간격은 눈이 아니라 **바운딩 박스로 계산해 확인한다**:

```js
const box = ([x,y,rx,ry]) => [x-rx, x+rx, y-ry, y+ry];
// 두 박스의 x·y 각 축 최소 간격을 구해 hypot
```

- 실측 결과 14px 미만인 쌍은 둘뿐이다 — **시칠리아~몰타 0px(오류·수정함)**, 사르데냐~코르시카 1px(**맞음** — 보니파초 해협은 실제로 11km).
- 즉 "가까운 것"과 "붙은 것"은 다르다. 붙어도 되는 곳은 없고, **1px이라도 바다색이 지나가야** 두 섬으로 읽힌다.
- 새 섬을 넣거나 옮기면 이 계산을 다시 돌린다.

## 그리는 순서 (mapSprite)

순서가 어긋나면 화면이 망가진다. 특히 4번은 필수.

```
1. 육지 찍기 (land 불리언 → 가로 런 단위로 P.grnM)
2. 섬 타원
3. ★ 육지 마스크 확보 (getImageData) — isLand(x,y)
4. 지대 색조 (사막/관목/삼림)   ← isLand 안에서만
5. 내륙 얼룩 16000점            ← isLand 안에서만
6. 산맥                          ← isLand 안에서만
7. outline ×4 (백사장 → 천해 → seaL → 심해 경계)
8. destination-over 로 외해 그라데이션
9. 해류 결                       ← 육지 근처 제외
```

**4~6에서 `isLand` 검사를 빠뜨리면 대참사.** 실제로 한 번 당했다: 텍스처를 전체 캔버스에 뿌렸더니 7번 `outline()`이 바다에 흩뿌려진 점 하나하나에 테두리를 그려 화면 전체가 청록 격자무늬가 됐다. → [pixel-pipeline.md](pixel-pipeline.md)의 outline 함정

## 지대 경계 — 직선 금지

```js
desertY = (x) => 152 + sin(x*0.031)*7 + sin(x*0.011+2)*6;
scrubY  = (x) => 78  + sin(x*0.024+1)*12 + sin(x*0.009)*9;
```
`y > 152`처럼 상수로 자르면 화면을 가로지르는 **띠**로 보인다. sin 2개를 다른 주기로 겹쳐 흔들어야 자연스럽다. 아라비아 사막은 별도 조건(`x>352 && y>116+...`).

## 해안선 색 번짐

`outline()`을 색만 바꿔 4번 연속 호출하면 육지에서 바깥으로 4px 띠가 생긴다.

```
P.sandL(백사장) → #6fc4cc(초천해) → P.seaL → #2c6f8c
```
그 다음 `globalCompositeOperation = 'destination-over'`로 남은 빈 픽셀(외해)에 그라데이션을 깐다. 순서가 반대면 바다가 육지를 덮는다.

## 도시 배치

도시 좌표는 `js/data.js: CITIES`의 `x`/`y`(400×225 기준)에 있고 지형 파일과 분리돼 있다.
지형을 수정하면 도시가 육지 한복판이나 먼바다에 놓일 수 있으니 함께 확인할 것.
마커는 캔버스에 `arc()`로 그리므로(픽셀 스프라이트 아님) 지형과 별개로 항상 또렷하다.

## QUICKMAP-art §3에서 옮겨 온 지형·검수 함정 (2026-08-26)

> 접근빈도 분류 — **지도를 그릴 때만** 필요하고 인물·배 스프라이트 작업에서는 안 읽는다.
> **삭제가 아니라 이동이다**(verbatim).

- **육지 폴리곤을 나열하지 마라.** 지중해 같은 내해는 행별 수역 격자(`SEA_SPANS`)로 정의한다. 폴리곤 나열은 반도가 1px 선이 되거나(이탈리아) 통째로 잠긴다(그리스). 세 번 갈아엎고 확정된 구조라 **접근법을 바꾸기 전에 [map-terrain.md](map-terrain.md)를 읽는다.**

- **텍스처는 반드시 육지 마스크 안에만 찍는다.** 전체 캔버스에 뿌리면 뒤이은 `outline()`이 바다에 흩뿌려진 점마다 테두리를 그려 화면이 청록 격자무늬로 망가진다. (실제로 당함)

- **저해상 격자를 최근접으로 확대하면 4px 톱니.** 이중선형 보간 + 임계값 판정 + 약한 노이즈.

- **식생·사막 경계를 상수로 자르면 띠로 보인다.** 주기가 다른 sin 2개를 겹쳐 흔들 것.

- **섬은 격자가 아니라 확대 후 좌표로** 찍는다. 격자에 넣으면 스무딩에 먹혀 사라진다.

- **섬끼리의 간격은 눈이 아니라 바운딩 박스로 잰다.** 몰타를 시칠리아 남안에 **0px로 맞붙여** 놓은 적이 있다(한 덩어리로 보였다). 축척은 대략 **10km/px** — 실제 90km면 9px은 띄운다. 사르데냐~코르시카 1px은 **맞다**(보니파초 해협 11km). 새 섬을 넣거나 옮기면 전 쌍을 다시 계산할 것. → [map-terrain.md](map-terrain.md)

- **★ 게임 지도는 실제 지중해의 투영이 아니라 도식이다.** 도시 좌표를 실제 위경도에 최소제곱으로 맞춰 보면 **최대 55px**(화면 폭의 14%) 어긋난다 — 로도스와 알렉산드리아는 실제 경도가 거의 같은데 게임에선 x가 239/320이고, 튀니스는 실제로 시칠리아 서쪽인데 팔레르모보다 동쪽에 있다. **그래서 진짜 지리대로 그린 그림일수록 게임에서는 더 틀린다**(1차 지도 납품이 이것 하나로 반려됐다 — 도시 15/16곳이 해안선 밖, 항로 25/28개가 육지 관통). 지도를 그리거나 발주할 때는 **좌표를 먼저 놓고 지형을 거기에 맞춘다.** 크롭·확대로는 절대 못 맞춘다.

- **★ 기계 검수는 최소조건이지 합격조건이 아니다 — 2차 납품이 그 증거다.** 2차는 무손실(png와 픽셀 100% 동일)·좌표 정합·육지 비율까지 `check-map.py` 전 항목을 통과했는데, 눈으로 보면 지중해가 아니었다: 이탈리아가 삼각 쐐기, 그리스가 역삼각형, 해안선이 전부 직선 사선, 섬은 타원 얼룩, 고유색 **8색**(1차 PNG는 48색). 사실상 **도시·항로 그래프의 볼록껍질을 바다로 칠한 그림**이다 — 검사 항목만 역설계한 것이라 의뢰서 §4(반도·섬 실루엣)를 만족하지 않는다.
  - **원인은 또 의뢰서였다.** §0-A에서 "좌표를 먼저 놓고 지형을 맞춰라"고 했더니 그림쟁이가 **지형을 포기하는 방향**으로 맞췄다. 빠진 것은 **좌표를 이미 만족하는 실루엣 기준판** — 게임이 코드로 그리는 `SEA_SPANS` 지도가 정확히 그것인데 기준판 3종에 안 들어 있다. ✅ 그것을 4배로 뽑아 주는 것으로 해소됐다(`gen-map-tracing.mjs` → `-x4`·`-coast`). 재의뢰는 "이 실루엣에 질감·명암만 얹어라"다.
  - `check-map.py`에 **색수 하한(≥24색)과 해안선 직선 구간 길이 상한**을 넣어 이 우회를 막을 수 있다(미구현 — 색 수는 *많다*는 경고만 있다). 크래시 둘은 2026-08-17에 고쳤다: **Windows 콘솔 cp949**(판정 전에 유니코드 출력에서 죽었다) · **리포 밖 경로**의 `relative_to()`(납품물을 다운로드·후처리 폴더에서 검수하면 반드시 밟는다 — "상대경로"가 조건이라고 적혀 있던 것을 바로잡았다).

- **★★★ 이 축척에서는 사실적 해안선과 직선 항로가 양립하지 않는다 — 재론 금지.** 400×225에서 1px ≈ 10~15km라 **연안 항로(5~20km)가 1~2px로 뭉개진다.** 그래서 실제 지리 해안선을 넣으면 직선 항로가 반도를 관통한다(3차 납품에서 52개 중 **18개**). 2026-08-17에 다섯 경로를 전부 시험했고 결과는 이렇다: ① 16:9 크롭 → 동지중해가 화면 밖(알렉산드리아가 뭍에서 64px) ② 세로 압축 → 이탈리아 반도·아드리아해·에게해 소멸 ③ **좌우 여백 채우기(레터박스) → 지형은 왜곡 0으로 온전했다. 여기까지는 성공** ④ 항구 좌표를 그림에 재배치 → 26/28곳은 의미대로 앉았지만 **이스탄불이 어느 경유로도 안 닿고**(에게해 북부가 막힘) 자동 경유는 "에게해에서 사르데냐를 돌아 아테네" 같은 무의미한 경로를 냈다 ⑤ 육지를 뒤로 물리기 → 3px 침식에 관통 4개로 줄지만 육지가 9.6%가 되어 **바다 90%**(검수 상한 80%) ⇒ **덧그리기만 성립한다** — `node tools/gen-map-tracing.mjs`가 4배 확대판과 해안선 판을 뽑고, 의뢰서 §4-B가 그것을 설명한다. 게임 지도가 도식인 이유가 바로 이 축척이다.

- **지도 아홉 장은 PNG다**(`assets/map/` · 코드 생성은 폴백 · 사람이 그린 것은 반려 중 F-1). **좌표를 옮기면 `node tools/gen-map-png.mjs`를 다시 돌린다** — 안 돌리면 `check-map.py`가 잡는다. ⚠️ **아홉 장만 미커밋**이다: 워킹트리판은 육지가 42px 주기로 반복되므로(F-8 · 바로 아래 항목) **그대로 커밋하면 반복 무늬가 저장소에 들어간다.** 고친 뒤 따로 커밋한다.

- **★ 지도에 질감을 얹을 때 사인파를 노이즈로 쓰지 마라 — 벽지 무늬가 된다.** `tools/enhance_map_texture.py`가 주석에 "Perlin-like"라 적고 `sin(x·0.15)·cos(y·0.15)`를 썼는데, **사인파 곱은 정의상 주기함수**라 육지가 **41.9px·17.9px 격자로 반복**된다(실측: 세로 42px 자기상관 **0.688**). 400px 폭에서 아홉 번 되풀이돼 눈에 그대로 보이고, `check-map.py`는 **9/9 통과**시킨다(§기계 검수는 최소조건의 또 다른 사례). 같은 스크립트가 `CLIMATE[].zones`를 안 읽어 **사하라와 사바나의 남북 구분도 지웠다**. 진짜 Perlin/값 노이즈는 격자마다 무작위 기울기를 뽑아 반복이 없다.

- **`pinIsles` 섬을 너무 크게 잡으면 "물이 안 닿는 항구"가 된다.** 검수기는 반경 6px 안에 물이 있는지 보는데, 7×5 타원은 그 범위를 거의 다 채운다 — 제주가 그래서 반려됐고 **4×3으로 줄여** 통과했다. 섬은 항구를 물가에 앉히려고 찍는 것이니 **주변에 물이 남을 만큼만** 찍는다.

- **섬이 곧 항구인 곳은 `auto.pinIsles`로 좌표에 박는다.** `landmass` 사각형에 넣으면 그쪽은 **저해상 격자**라 작은 섬이 스무딩에 먹혀 사라진다 — 쌍서(닝보 앞바다)가 그래서 몇 판 동안 물 위에 떠 있었다. `isles`(흩뿌림)는 "어디에 섬이 있어야 하는지"를 모르므로 맡기지 않는다.

- **그림 납품은 눈으로 받지 말고 `python tools/check-map.py`로 받는다.** 사람 눈은 "지중해처럼 생겼다"에서 멈추지만 스크립트는 도시 좌표와 항로를 픽셀로 찍어 본다. **손실 WebP도 여기서 걸린다** — 1차 납품은 PNG를 48색으로 잘 양자화하고도 손실 webp로 저장해 10,862색으로 번졌다(게임이 4배 확대하므로 번진 가장자리가 그대로 4배가 된다).
