- **[2026-08-11] #game #balance** — 대포를 **거리 구간제**로 재설계(`CANNONS.near`~`far` + `state.js: zoneFactor`/`armsAimAt`).
  - 도입 직후 검산에서 장포가 거리 10/50/90 전 구간 1위(0.59/0.49/0.38), 경포가 전 구간 꼴찌(0.53/0.39/0.26)로 나옴 — 선택지가 없는 상태였다.
  - 원인은 `range` 배율이 조준 판정대를 **전 구간에서** 넓혀준 것. 모든 대포가 "가까울수록 좋다"의 같은 곡선이라 피해 배율 순서가 그대로 강함 순서가 됐다.
  - 대안 3개(사거리 하향 / 조준 추가 하향 / 장전 턴)를 계산해 보고 전부 기각 — 각각 여전히 우위·초보자 함정·작업량 대비 무의미. 대신 **대포마다 잘 맞는 구간**을 주고 밖에서 조준이 무너지게 했다.
  - `range` 필드 폐기. 경포 0~40(피해 0.82→0.95), 중포 0~70(1.10→1.15), 장포 35~100. 구간 밖 기울기는 먼 쪽 50 / 가까운 쪽 25, 바닥 0.4.
  - 결과: 근접 경포(값도 절반) · 중거리 중포 · 원거리 장포로 1위가 갈린다. 무장 탭에 구간 막대와 거리별 조준 배율 요약을 추가.
  - 검산은 `state.js`+`battle.js` 공식을 그대로 옮긴 Node 스크립트로. 실화면에서도 조준 띠 폭을 측정해 일치 확인(장포 거리78 20.2% / 경포 거리59 22.6%).

- **[2026-08-11] #engine #fix** — 개발 서버를 `serve.py`(no-store)로 교체. `python -m http.server`는 쓰지 않는다.
  - 증상: 코드를 고친 뒤 새로고침하면 **화면이 통째로 검게** 나왔다. 캐시 없는 새 프로필에서는 정상 부팅해 코드 문제가 아님을 먼저 확인.
  - 원인: `-m http.server`가 `Cache-Control`을 안 보내 브라우저가 .js를 휴리스틱 캐시한다. 새 `index.html`·`main.js` + 낡은 `state.js` 조합에서 `armsAimAt`을 못 찾아 **모듈 링크가 통째로 실패** → 스크립트가 한 줄도 안 돎. 서버 로그에 `index.html`·`main.js`만 200이고 나머지 모듈 요청이 없는 것이 결정적 단서였다.
  - 조치: `serve.py`(`Cache-Control: no-store` + ThreadingHTTPServer). 이미 캐시를 문 탭은 `Ctrl+Shift+R` 또는 **다른 포트**로(포트가 다르면 캐시가 분리된다).
  - 그 과정에서 만든 버그도 수정: 로그 필터가 `log_error`의 정수 인자에 `in`을 써서 favicon 404 처리 중 예외 → 연결이 끊겨 `ERR_EMPTY_RESPONSE`. 문자열일 때만 거르도록 가드.
