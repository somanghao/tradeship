# tradeship — 지중해 교역기

대항해시대 2 풍의 지중해 무역·전투 캐주얼 게임. 웹(순수 ES 모듈 + Canvas, 빌드 없음), 픽셀아트.

## ★ 세션시작 필독 (BLOCKING)

1. **이 파일** + **`wiki/gotchas.md`**(도메인 무관 함정) 를 반드시 먼저 읽는다.
2. **작업 대상이 정해지면 `QUICKMAP.md`를 Read**해 도메인을 고르고, 해당 `QUICKMAP-<도메인>.md`로 간다.
   도메인 파일은 `§1~2 키워드→문서` + `§3 그 도메인 전용 함정`이라 자족적이다.

도메인: **art**(픽셀 에셋·지형·배경) / **game**(경제·전투 규칙) / **engine**(캔버스·씬·UI·실행)

## 절대 원칙

- 웹 출력은 claude.ai Artifact 금지 — **로컬 HTML + 로컬 서버(`python serve.py`) + 브라우저**(사용자 지침).
- 에셋은 `js/sprites/`에 모아 **팩토리 함수만 노출**한다. 나중에 렌더링 이미지로 교체 가능하게(사용자 지침).
- 이미지 기준: **2D 픽셀 형태, 고급스러울 필요는 없지만 싸구려로 보이면 안 된다**(사용자 지침).

## 핵심 모델

- 논리 해상도 **400×225** 고정. 캔버스는 무대 전체, 게임 화면은 그 안에 정수배 중앙 배치(레터박스).
- **그림은 캔버스, 글자·버튼은 DOM 오버레이.** 픽셀 폰트 없이 한글 가독성을 얻는 방법.
- 모든 스프라이트는 `bake(key,…)` 캐시 — 매 프레임 호출해도 비용 0, 대신 수정 후 새로고침 필요.
- 씬: `port`(무역) ↔ `map`(항해) → `battle`(포격전→백병전), `port` → `shipyard`(선박·선원·무장·개장).
- 모듈 방향은 `data → state → world → scenes` **한 방향**이다. `world.js`(NPC)가 state를 쓰고, state는 world를 모른다(순환 참조 방지).
- **UI가 그림을 가리면 안 되는 화면은 패널을 `viewport()` 논리좌표에 얹는다** (조선소 씬이 본보기).

## 현재 상태

- 게임 루프 3파트(무역·항해·전투) + 조선소 전 구간 구현·브라우저 실동작 검증 완료.
- **공개 저장소**: `https://github.com/somanghao/tradeship` (public, main).
- **세 영역이 서로를 안 건드리게 갈라져 있다** — 그림(`assets/`·`js/sprites/`) / NPC(`js/npc/`·`world.js`) / 지도(`js/map/geo.js`). 경계와 절차는 `CONTRIBUTING.md`.
- 에셋은 전부 코드 생성: 병종(3포즈) · 선박(측면·탑다운) · 배경(지도/항구/외해) · 교역품 아이콘 · 전투 이펙트 · 대포.
  **코드를 안 고치고 PNG로 갈아 끼울 수 있다** — `bake` 키를 `assets/manifest.json`에 적으면 그 스프라이트만 대체된다(키는 `preview.html`에 표시).
- **경제 대시보드** `/dashboard/` — 게임 모듈을 그대로 돌려 시세·현금흐름·물동량·NPC를 계측한다(재구현 아님).
  "가격이 실제로 움직이나 · 부족한 항구에 물자가 닿나"를 눈이 아니라 수치로 본다.
- 콘텐츠 수치(교역품·선종·적 티어·대포·개장·탄종)와 도시 경제(`CITY_TRADE`)는 `js/data.js`, 도시 좌표·항로·해류는 `js/map/geo.js`가 정본 — 여기에 세지 않는다(추가할 때마다 어긋난다).
- **도시 데이터는 세 겹이다** — ①UI(`map/geo.js`: 좌표·깃발) ②테이블(`data.js: CITY_TRADE`: 수치) ③**근거**(`content/city-evidence.json`: 판정·사료·출처). 수치를 고치면 근거도 같은 커밋에서 고친다 — `node tools/check-evidence.mjs`가 어긋나면 실패시킨다. 대시보드 **근거** 모드가 같은 JSON을 읽어 칸마다 배지·출처를 띄운다.
- 특산품과 깃발은 15~16세기 사료에 맞춰져 있고 "게임성 때문에 일부러 덮어쓴 곳"도 따로 적혀 있다. 밸런스만 보고 되돌리면 같은 오류가 재발한다.
- **아나톨리아 안쪽 시장**(부르사=생사 1차시장·이즈니크=도자기 본산)은 이스탄불에서만 들어가는 막다른 주머니다. 둘 다 실제로는 내륙이라 항구로 둔 것이 의도적 예외.
- **시작은 물이 새는 낡은 바사 + 금화 900.** 항해할 때마다 선체가 삭아 갈아탈 압박이 걸린다. 첫 목표는 제대로 된 배 사기.
- **배는 도시 공업력(`map/geo.js: industry` 0~3)이 정한다** — `SHIPS[].tier` 이상이어야 짓고, 제 나라 배는 한 등급 쉽다. 신형(`era: modern`)과 최상급은 **선행 선종을 몰아 봐야**(`requires`·`state.everOwned`) 열린다. 즉시 손에 넣으려면 **중고선**(`usedListings`)이 있고, 튀니스·알제는 나포선 개조항이라 더 싸게 나온다. → `wiki/shipyard.md`
- 조선소(전용 씬·탭): **선단**(여러 척 보유·항구별 정박·자동 매각 없음·정박 유지비) / **갑판 배치**(6칸 직접 지정→백병전 직결) / **무장**(경포·중포·장포 — 대포마다 잘 맞는 거리 구간이 있어 근접/중거리/원거리 1위가 갈린다. 실린 대포는 부두에 실물로 보인다. 하단에 특수탄 탄약고) / **개장**(배마다 영구히 붙고 갈아타면 그 배 것을 쓴다) / **중고**(즉시 손에 넣는 유일한 길 — 싸지만 선체가 상해 있다).
- 전투는 **탄종 선택**이 한 축 — 포도탄(선원)·사슬탄(돛→적 기동·도주 봉쇄)·가열탄(화재). 백병전으로 이기면 적선을 선단에 편입한다. → `wiki/battle-system.md`
- **부관은 오직 한 명, 에이미다** — 이 바다에서 이름을 가진 사람은 선장과 그뿐이다. 항해술·전투는 손대지 않고 **오직 돈만** 만진다(세금·시장압력·계약·흥정). 보수는 **동업자 몫으로 두 갈래** — 고정 급여 16닢/일 + 매각 이익의 11%. 그래서 **거래가 작으면 손해고 커질수록 남는다**. 베네치아에서만 만나고, 물 새는 배를 모는 선장에게는 오지 않는다. 급여·성과급·능력은 **한 묶음**이라 함께 재측정한다(총액이 같아도 급여와 성과급은 효과가 다르다). → `wiki/officer.md`
- **세계가 혼자 돈다** — 상인·해적 NPC가 실제로 사고팔고 서로 습격한다. 그 거래가 플레이어가 보는 시세에 압력으로 남는다. 바다에서 만나면 흥정하거나 덮칠 수 있다. → `wiki/world-npc.md`
- **경제는 "여러 항차를 굴려 모으는 길"과 "대형 주문 한 건을 무는 길"이 나란하다.** 시장 깊이·입항세·일당/보급/선단 유지비·바람과 해류가 속도를 정한다. 곡선은 `node tools/sim-trade.mjs`로 검증한다 — 눈으로 판단하지 않는다. → `wiki/economy-trade.md`

## 다음 후보 (사용자에게 선택 요청해 둔 상태)

- **백병전 연출** — 포즈 전환뿐. `pixel.js: blitTinted`가 준비돼 있으나 미사용.
- **세이브/로드** — 없음(새로고침 시 초기화). `state.known`·`everOwned`가 **Set**이고 `fleet`(배별 `arms`·`refits`)·`shots`·`towing`·`officer`까지 함께 직렬화해야 한다.
- **바람/방향** — 항해에는 들어갔지만 **포격 페이즈에는 없다.** 선회가 거리 조절로만 추상화돼 있다.
- **자산 sink** — 부관 성과급이 첫 sink지만 후반 금화를 다 받아내지는 못한다. 항구 투자·도시 건물·상점 매입이 다음 자리(사용자 구상).

보류: 사운드 없음 · 라틴세일 형태 뭉툭(게임에선 거슬리지 않아 방치) ·
대포를 배 현측 포문에 물린 모습으로 표현(포문 수 ≠ 대포 수라 규칙부터 손봐야 함 — 지금은 부두에 늘어놓는다).
