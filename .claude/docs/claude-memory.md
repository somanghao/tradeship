# tradeship — 지중해 교역기

대항해시대 2 풍의 지중해 무역·전투 캐주얼 게임. 웹(순수 ES 모듈 + Canvas, 빌드 없음), 픽셀아트.

## ★ 세션시작 필독 (BLOCKING)

1. **이 파일** + **`wiki/gotchas.md`**(도메인 무관 함정) 를 반드시 먼저 읽는다.
2. **작업 대상이 정해지면 `QUICKMAP.md`를 Read**해 도메인을 고르고, 해당 `QUICKMAP-<도메인>.md`로 간다.
   도메인 파일은 `§1~2 키워드→문서` + `§3 그 도메인 전용 함정`이라 자족적이다.
3. **"마지막 작업이 뭐였나"를 물으면 `git log` + `changelog.md` 맨 위**를 본다 — 이 파일은 *최종상태*만 담고 경위는 담지 않는다.

도메인: **art**(픽셀 에셋·지형·배경) / **trade**(경제·물가·NPC·고증) / **combat**(전투·선박·조선소) / **engine**(캔버스·씬·UI·실행)

## 절대 원칙

- **★ 콘텐츠는 풍부하게, 금액은 근거에 충실하게 — 이 둘을 섞지 않는다(최상위 지침).**
  - **콘텐츠**(배·교역품·도시·해적·사건의 *종류*)는 **많을수록 좋다. 어떤 장치도 이것을 제약해선 안 된다.**
    근거가 아직 없다는 이유로 도시·품목·선종을 못 넣으면 안 된다 — **먼저 넣고 근거는 뒤따른다.**
  - **금액·시세**(값·비율·위험도)는 사료에 충실하고 현실적이어야 한다. **돈은 어렵게 벌려야 재미가 있다** —
    수익을 올려 달라는 압력이 오면 근거부터 확인하고, 근거가 아니라 편의면 올리지 않는다.
  - ⚠️ **검증 스크립트가 콘텐츠를 억제하는 장치가 되기 쉽다.** 그래서 실패/경고를 갈라 둔다:
    **실패**(exit 1)는 *코드와 근거가 어긋남·규칙이 자기모순*일 때만. **경고**는 밴드 이탈·미조사.
    "근거 없음"으로 실패시키면 콘텐츠를 늘리려 조사부터 끝내야 하는 구조가 된다.
- **연도를 고정하지 않는다 — 배경은 "대항해시대쯤"이다(최상위 지침).** 특정 해에 맞추면
  그 해에 없던 도시·세력·선종을 계속 덜어내야 하고 수정 범위가 눈덩이처럼 커진다.
  **콘텐츠가 풍성한 쪽을 택한다 — 이왕이면 모두 나오게 한다.** 그래서 실제로는 공존하지 않은
  것이 한 화면에 있을 수 있다(기사단령 로도스 ↔ 기사단령 몰타). 그런 항목은 근거 JSON에
  `verdict: "gameplay"`로 표시해 **알고 그렇게 뒀다**는 것을 남긴다.
  개별 사실의 고증(무엇이 어디서 났나, 어느 항로가 위험했나)은 여전히 사료를 따른다.
- 웹 출력은 claude.ai Artifact 금지 — **로컬 HTML + 로컬 서버(`python serve.py`) + 브라우저**(사용자 지침).
- 에셋은 `js/sprites/`에 모아 **팩토리 함수만 노출**한다. 나중에 렌더링 이미지로 교체 가능하게(사용자 지침).
- 이미지 기준: **2D 픽셀 형태, 고급스러울 필요는 없지만 싸구려로 보이면 안 된다**(사용자 지침).

## 핵심 모델

- 논리 해상도 **400×225** 고정. 캔버스는 무대 전체, 게임 화면은 그 안에 정수배 중앙 배치(레터박스).
- **그림은 캔버스, 글자·버튼은 DOM 오버레이.** 픽셀 폰트 없이 한글 가독성을 얻는 방법.
- 모든 스프라이트는 `bake(key,…)` 캐시 — 매 프레임 호출해도 비용 0, 대신 수정 후 새로고침 필요.
- 씬: `port`(무역) ↔ `map`(항해) → `battle`(포격전→백병전), `port` → `shipyard`(선박·선원·무장·개장).
- 모듈 방향은 `data → state → world → scenes` **한 방향**이다. `world.js`(NPC)가 state를 쓰고, state는 world를 모른다(순환 참조 방지).
- **UI가 그림을 가리면 안 되는 화면은 패널을 `viewport()` 논리좌표에 얹는다** (조선소 씬이 본보기).

## 현재 상태

- 게임 루프 3파트(무역·항해·전투) + 조선소 전 구간 구현·브라우저 실동작 검증 완료.
- **공개 저장소**: `https://github.com/somanghao/tradeship` (public, main).
- **세 영역이 서로를 안 건드리게 갈라져 있다** — 그림 / NPC / 지도. 경계와 절차는 `CONTRIBUTING.md`.
- 에셋은 전부 코드 생성: 병종(3포즈) · 선박(측면·탑다운) · 배경(지도/항구/외해) · 교역품 아이콘 · 전투 이펙트 · 대포.
  **코드를 안 고치고 PNG로 갈아 끼울 수 있다** — `bake` 키를 `assets/manifest.json`에 적으면 그 스프라이트만 대체된다(키는 `preview.html`에 표시).
- **통합 대시보드** `/dashboard/` — 사이드바 4탭(경제·해적·항구·보수). 게임 모듈을 그대로 돌려 계측한다(재구현 아님). "가격이 실제로 움직이나 · 부족한 항구에 물자가 닿나 · 부관은 값을 하나"를 눈이 아니라 수치로 본다. 탭별 내용·추가 절차 → `QUICKMAP-trade.md`
- 콘텐츠 수치(교역품·선종·적 티어·대포·개장·탄종)와 도시 경제(`CITY_TRADE`)는 `js/data.js`, 도시 좌표·항로·해류는 `js/map/geo.js`가 정본 — 여기에 세지 않는다(추가할 때마다 어긋난다).
- **데이터는 세 겹이다 — UI ▸ 수치 ▸ 근거.** 도시는 `map/geo.js` ▸ `data.js: CITY_TRADE` ▸ `content/city-evidence.json`, 항로 위험도도 같은 꼴이다. **수치를 고치면 근거도 같은 커밋에서 고친다** — `check-*` 스크립트가 어긋나면 실패시킨다(단 *근거가 아직 없는 것*은 경고일 뿐 — 위 절대 원칙).
- 특산품과 깃발은 15~16세기 사료에 맞춰져 있고 "게임성 때문에 일부러 덮어쓴 곳"(`verdict: gameplay`)도 따로 적혀 있다. 밸런스나 연표만 보고 되돌리면 같은 오류가 재발한다.
- **아나톨리아 안쪽 시장**(부르사·이즈니크)은 이스탄불에서만 들어가는 막다른 주머니고, **몰타**는 해협 병목의 **나포선 경매항**(`prizeYard`)이다. 셋 다 의도적 예외 — 앞의 둘은 실제로 내륙이고, 몰타는 나포품을 `supply`로 넣지 않았다(산지보다 싼 향신료 창구가 생겨 경제가 쏠린다). → `wiki/city-goods-history.md`
- **시작은 물이 새는 낡은 바사 + 금화 900.** 항해할 때마다 선체가 삭아 갈아탈 압박이 걸린다. 첫 목표는 제대로 된 배 사기.
- **배는 도시 공업력이 정하고**(`industry ≥ SHIPS[].tier`), 상급선은 선행 선종을 몰아 봐야 열린다. 즉시 손에 넣는 길은 **중고선**뿐. 조선소는 전용 씬 4탭(선단·갑판 배치·무장·개장·중고). 전투는 **탄종 선택**(포도탄·사슬탄·가열탄)이 한 축이고 백병전으로 이기면 적선을 선단에 편입한다. → `QUICKMAP-combat.md` · `wiki/{shipyard,battle-system}.md`
- **부관은 오직 한 명, 에이미다** — 이 바다에서 이름을 가진 사람은 선장과 그뿐이다. **등용하는 인물이 아니라 첫날부터 타고 있는 동행**이라 계약금도 면접도 해고도 없다. 항해술·전투는 손대지 않고 **오직 돈만** 만진다(세금·시장압력·계약·흥정). 보수는 고정 급여 + 매각 이익 배분이고, 급여·성과급·능력은 **한 묶음**이라 함께 재측정한다. 수치·사료 대조·짝비교 결과 → `wiki/officer.md`
- **세계가 혼자 돈다** — 상인·해적 NPC가 실제로 사고팔고 서로 습격한다. 그 거래가 플레이어가 보는 시세에 압력으로 남는다. 바다에서 만나면 흥정하거나 덮칠 수 있다. NPC 해적은 턴 만큼 부유해져 **현상금에 상한이 없다**(최상위 등급의 몇 배까지 간다). → `wiki/world-npc.md`
- **항로마다 위험이 다르다** — 근거는 **당대 해상보험 요율**(`map/geo.js: ROUTE_RISK`)이고, 거기에 그 구간에 실제로 뜬 해적 수가 얹힌다. 조우 확률 10~28%(평균은 종전 고정값 18%와 같다 — 총량은 두고 갈랐다). 오스만 내해·육로는 **해적 대신 노상강도·통행세**가 난다(`INLAND_ODDS`). 실효 조우율은 시드 20판 평균 18%대·내해 통과 7%로 **종전과 사실상 같다**(`node tools/sim-risk.mjs`).
- **경제는 "여러 항차를 굴려 모으는 길"과 "대형 주문 한 건을 무는 길"이 나란하다.** 곡선은 `node tools/sim-trade.mjs`로 검증한다 — 눈으로 판단하지 않는다. → `wiki/economy-trade.md`
- **물가와 임금은 당대 사료 비율에 맞춰져 있다**(근거는 카테고리별 4파일 — 교역품·임금·자산·유지비). 대조 축은 둘뿐이다 — **곡물의 몇 배인가**(품목 상대가격)와 **선원 연봉으로 무엇을 몇 개 사나**. 게임 화폐 ‘닢’은 실화폐가 아니라 절대액 환산은 하지 않는다.
- **항해비는 일곱 갈래로 갈라져 있고 저마다 다른 성장 요인에 붙는다** — 일당·보급(선원 수) · 선체 유지(배 크기) · 무장 유지(대포 수) · 선단(쟁여둔 배) · **적하보험**(화물 가치 × 항로 요율) · 부관 급여. 임금을 사료 쪽으로 내린 대신 **성장할수록만 무거워지는 쪽**으로 압박을 옮긴 결과다.
- **값나가는 짐은 두 번 대가를 치른다** — 보험료가 오르고(`INSURANCE_RATE`), 해적 조우 확률도 오른다(`state.js: cargoLure`, 9,000닢당 +5%p·상한 +14%p). 그래서 초반엔 곡물·소금을 안전한 이웃으로 나르고, 커져야 향신료·비단에 손을 댄다.
- **큰돈은 확률이 아니라 사건에서 나온다** — 노이즈(`wobble` ±15%)로는 ×1.5를 못 넘는데 사료의 대박은 그보다 크다. 그래서 `state.shocks`가 도시·품목 하나의 시세를 한동안 밀어 올리거나 내린다: **기근·봉쇄**(↑) · **풍작/독점 붕괴**(↓) · **NPC 상인이 털리면 그가 대던 항구**(↑). 종류·확률은 `data.js: SHOCK.events`가 정본이고, 후보 도시는 매번 `CITIES`에서 만들어 **도시·품목을 늘리면 사건도 저절로 는다**. 지도 화면 "뱃사람들의 소문"이 지금 흔들리는 곳을 띄운다.
- **보험은 실제로 보상한다** — 폭풍이 심하면 짐을 던지고(공동해손) 잃은 값의 `INSURANCE_COVER`만큼 받는다. 요율 계수와 같은 값이라 **낸 만큼만 받는다**. 화물 손실 사건은 시드 20판 평균 **20항차에 1건**으로, 사료의 보험료 중앙값 5%·전손률 4.7%가 가리키는 빈도와 같다.

## 다음 후보 (사용자에게 선택 요청해 둔 상태)

- **부동산·거점을 자산 sink로** — 항구별 창고·상관. 사료 앵커는 `content/asset-evidence.json`에 있고 대시보드 **항구** 탭이 배율로 환산해 보여준다. 게임 기능은 미구현.
- **그림 발주** — 항구 배경 16장은 의뢰서만 있고 그림이 없다. **지도는 2차까지 반려**(`assets/map/`에 보관·`manifest.json`은 비어 있음 — 붙이면 항구 점이 엉뚱한 자리에 찍힌다). 1차는 실제 지중해를 정확히 그려 **게임 좌표계(도식)와 어긋났고**(도시 15/16곳 해안선 밖), 2차는 `check-map.py`를 통과하지만 **도시·항로 그래프의 볼록껍질을 바다로 칠한 것**이라 반도·섬 실루엣이 없다(고유색 8색). 빠진 것은 **좌표를 이미 만족하는 실루엣 기준판** — 코드 생성 지도(`SEA_SPANS`)를 4배로 뽑아 주고 "이 실루엣에 질감만 얹어라"로 재의뢰하는 것이 다음 수. 지금 지도는 코드 생성본이라 섬이 전부 타원이다.
- **백병전 연출** — 포즈 전환뿐. `pixel.js: blitTinted`가 준비돼 있으나 미사용.
- **세이브/로드** — 없음(새로고침 시 초기화). `state.known`·`everOwned`가 **Set**이고 `fleet`(배별 `arms`·`refits`)·`shots`·`towing`·`officer`까지 함께 직렬화해야 한다.
- **바람/방향** — 항해에는 들어갔지만 **포격 페이즈에는 없다.** 선회가 거리 조절로만 추상화돼 있다.


보류: 사운드 없음 · 라틴세일 형태 뭉툭(게임에선 거슬리지 않아 방치) ·
대포를 배 현측 포문에 물린 모습으로 표현(포문 수 ≠ 대포 수라 규칙부터 손봐야 함 — 지금은 부두에 늘어놓는다).
