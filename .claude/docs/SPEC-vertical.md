> 사용자가 요구한 것: *"산지에 농장도 만들고 유통 선단을 만들어 유통라인 확보하고 가공공장 판매샵 등 수직계열화"*,

## 0. 이 사양이 먼저 답해야 하는 것 — **"돈이 쉬워지지 않는가"**

### 0-1. 문제

이 저장소의 절대 원칙과 정면으로 부딪힌다.

- *"**돈은 어렵게 벌려야 재미가 있다** — 수익을 올려 달라는 압력이 오면 근거부터 확인하고, 근거가 아니라 편의면 올리지 않는다"*
- `HEGEMONY` 주석: *"**보상으로 돈이나 수입을 주지 않는다.** … 새 수입원을 만들면 '돈은 어렵게 벌려야 재미가 있다'가 통째로 무너진다"*
- `MARKET` 주석: 대량거래 벌점은 *"성장할수록만 무거워지는 브레이크"*다

수직계열화는 겉보기에 **새 수입원**이다. 그러므로 이 사양의 성패는 §0-2의 정리 하나에 달려 있다.

### 0-2. ★ 정리 — **사슬은 시세보다 비싸다**

> **원료를 시세로 사서 가공하면, 그 완제품을 산지에서 사는 것보다 손해다.**

밸런스 감이 아니라 §2-3의 **가공마진 밴드(1.08~1.25)**와 기존 `SPREAD 0.70`이 만드는 산술적 결과다.
검산 둘 — 지금 코드의 실제 배율을 넣었다.

**① 설탕** (푼샬 · `sugar 0.44` · 사탕수수를 `cane 0.46`으로 신설)

| | 계산 | 값 |
|---|---|---|
| 사탕수수 시세 | `34 × (1 + (0.46−1)×0.70)` | 21.1닢/칸 |
| 사슬 조달가 | 사탕수수 7칸 148 + 가공비 28 | **176닢/칸** |
| 그냥 사기 | `280 × (1 + (0.44−1)×0.70)` | **170닢/칸** |
| | | **사슬이 3.5% 비싸다** |

**② 은** (포토시 · `silver 0.44` · `silverore 0.44` 신설 · 수은은 말라가 `0.62`)

| | 계산 | 값 |
|---|---|---|
| 사슬 조달가 | 은광석 15칸 283 + 수은 1칸 226 + 가공비 96 | **302닢/칸** (은 2칸) |
| 그냥 사기 | `480 × (1 + (0.44−1)×0.70)` | **293닢/칸** |
| | | **사슬이 3.1% 비싸다** |

**곧 가공장 하나만 사면 손해다.** 사슬이 이기기 시작하는 것은 오직 두 조건이 붙을 때다:

1. **생산 시설(농장·광산)이 원료를 원가로 준다** — 시세의 −12~−24%
2. **그 원가분은 `impact`를 쌓지 않는다** — 자기 밭에서 실었기 때문이다

★ 그러므로 이 설계는 **네 층을 다 가져야 남는다.** 한 층만 사면 벌을 받는다.
이것이 "수직계열화"라는 말의 정직한 번역이고, 이 사양의 가장 강한 방어다.

### 0-3. ★ 방어 일곱 — 무엇이 곡선을 붙잡는가

| # | 장치 | 왜 곡선이 안 꺾이나 |
|---|---|---|
| **①** | **가공마진 밴드 1.08~1.25** | 가공 자체로는 8~25%밖에 안 남고, 가공비 10%가 그중 절반을 먹는다. §0-2의 정리가 여기서 나온다 |
| **②** | **대량거래 벌점을 투입 비율만큼 더 받는다** | 설탕 60칸을 만들려면 사탕수수 **420칸**을 사야 한다. `impact`가 420만큼 쌓여 `MARKET.cap 0.50`에 곧바로 닿는다 — **가공장은 규모를 키울수록 원가가 오른다.** 기존 브레이크가 사슬 맨 앞에서 **7배로** 작동한다 |
| **③** | **생산 시설의 산출은 하루 단위로 묶인다** | 농장 4~10칸/일 · 광산 2~6칸/일 · 재고 상한 45일치. 대형선 320칸을 원가로 채울 수 없다. **그 항구를 자주 들러야만** 이득이 쌓인다 |
| **④** | **고정비가 규모에 비례해 붙는다** | `state.works` 총 투자액의 **연 10%**를 30일마다(거점 6%보다 무겁다). 못 내면 휴업 → 압류. 패권과 같은 구조다 |
| **⑤** | **자본이 배 밖에 묶이고, 매각하면 40%가 증발한다** | 시설 매각 회수율 **60%**. 지금 게임의 성장은 "금화 → 큰 배 → 화물칸"인데 시설에 넣은 돈은 배가 되지 않는다 |
| **⑥** | **자본 연수익률이 무역 회전보다 낮다** | §0-4 참조. **초·중반에 사슬을 짓는 것은 명백히 손해다.** 사슬의 자리는 *"배에 더 못 넣는 돈"*의 행선지이고, 그 자리는 A-1 거점이 이미 정의했다 |
| **⑦** | ★ **가장 값나가는 갈래에는 임자가 있다** | 정향·육두구·계피·일본 은은 **돈으로 못 산다**(§5 독점). 면허를 사거나, 밀조하다 몰수당하거나, 싸워서 뺏어야 한다. **돈이 쉬워지지 않는 것이 밸런스 축만이 아니라 콘텐츠 축에서도 지켜진다** |

★ **⑥과 ⑦이 이 설계의 핵심이다.** 곡선이 위로 안 꺾이는 이유는 브레이크를 걸어서가 아니라
**사슬이 초·중반의 최적해가 아니고, 후반의 최상급 사슬은 돈만으로 열리지 않기 때문**이다.
최적 플레이 시뮬(`sim-core.mjs`)이 사슬을 20항차 전에 짓는다면 그것은 값이 틀린 것이고,
§6-3의 기각선이 그것을 잡는다.

### 0-4. 값 검산 — 완성된 사슬 하나의 수익률

설탕 사슬(푼샬 농장 L2 + 제당소 L2 → 안트베르펜 창고 + 판매소 L1)

| | 값 |
|---|---|
| 투자 합계 | 농장 7,191 + 제당소 56,520 + 푼샬 창고 8,000 + 안트베르펜 창고 24,000 + 판매소 24,480 = **120,191닢** |
| 30일 고정비 | `works` 88,191 × 0.833% = 735 + `holdings` 32,000 × 0.5% = 160 = **895닢** |
| 30일 산출 | 농장 L2 7칸/일 × 30 = 사탕수수 210칸 → **설탕 30칸** (제당소 L2 5칸/일 → 6일 소요) |
| 조달 원가 | 사탕수수 원가 17.2 × 210 = 3,612 + 가공비 840 = 4,452 → **칸당 148닢** |
| 판매 실수령 | 안트베르펜 `demand 1.30` → 339, 관세 6% · 판매소 감쇠 후 실효 압력 4% → **칸당 306닢** |
| **30일 순이익** | (306−148) × 30 − 895 = **3,845닢** |
| **자본 연수익률** | 3,845 × 12 ÷ 120,191 = **38%/년** |
| **회수기간** | **938 게임일** — 캠페인 전체 항해일(900~1,100)과 같다 |

> ★ **회수 938일은 실패가 아니라 설계 목표다.** 견줄 대상은 무역이 아니라 **거점**이다 —
> `HOLDINGS`는 회수가 **아예 없고**(순전히 지출이다), 사슬은 *"돈이 아주 조금 돌아오는 지출"*이다.
> 반대로 같은 120,000닢을 화물 회전에 넣으면 항차 ROI 10% × 연 30회전이라 이론상 훨씬 낫다.
> **그런데 후반에는 그 돈이 배에 다 안 들어간다** — 그것이 A-1을 만든 이유였다
> (*"배 꼭대기를 사고 나면 금화가 갈 데가 사라진다"*). 사슬은 그 자리를 나눠 갖는다.

### 0-5. 기각 조건

★ **순이익 곡선이 크게 위로 꺾이면 이 설계는 틀린 것이다.** 판정선은 §6-3에 수치로 있다.
요약하면 **60항차 총자산 중앙값이 기준선의 ×1.20을 넘으면 기각**이고,
**고정비/총지출 비중이 +8%p 이상 오르지 않으면 목적을 못 이룬 것**이다.

## 1. 열 갈래 — 무엇을 고르고 무엇을 버렸나

### 1-1. 고른 기준

사용자 지시가 기준을 정했다 — **"당시 유럽에서 가장 가치가 큰 것 = 가장 부유한 나라들이 원했던 것"**.
곧 **16세기 유럽의 수입 결제 흐름을 실제로 지배한 품목**이고, 그것을 사료로 확인해 열로 좁혔다.

버린 것도 적어 둔다(초안에는 있었다) — 브랜디 · 청동 · 화약 · 무기 · 선재 · 무두가죽 · 철 · 보석세공.
전부 사슬로 성립하지만 **유럽이 아시아·신대륙에서 *원했던* 것이 아니라 유럽이 스스로 만들던 것**이다.
사용자의 기준선 밖이므로 이 문서에서 뺀다. 근거는 §9-③에 남긴다(다음에 넓힐 때의 목록이다).

### 1-2. ★ 열 갈래 확정

「층」 = 그 갈래가 실제로 갖는 계열화 단계. **가공이 없는 갈래가 셋 있다** — 그 셋은 대신 **독점**이 걸린다.

| # | 갈래 | 층 | 왜 유럽이 원했나 (근거 요지) | 산지 |
|---|---|---|---|---|
| **1** | **설탕** ★본보기 | 생산 → **가공** → 유통 → 소매 | 플랜테이션의 원형. 농장·제당소·유통이 한 몸이었고 마데이라 → 상투메 → 브라질 → 카리브로 그 모델이 그대로 옮겨 갔다 | 푼샬 · 상투메 · 헤시피 · 바베이도스 |
| **2** | **비단** ★본보기 | 생산 → **가공** → 유통 → 소매 | 생사 → 직물의 가공 단계가 가장 뚜렷하다. 루카·제노바·베네치아 견직업이 중국·페르시아 생사로 굴러갔다 | 닝보 · 광저우 · 부르사 |
| **3** | **면포(캘리코)** ★본보기 | 생산 → **가공** → 유통 → 소매 | 인도 직물이 유럽 시장을 뒤집었다. 값이 아니라 **물량**으로 이긴 유일한 아시아 공산품 | 구자라트(캄바이·수라트) · 코로만델 |
| **4** | **염료(인디고·코치닐)** ★본보기 | 생산 → **가공** → 유통 → 소매 | **부피 대비 값이 가장 크다.** 코치닐은 신대륙에서 은 다음가는 수출품이었다 | 구자라트(인디고) · 누에바에스파냐(코치닐) |
| **5** | **은** | 생산 → **가공(제련)** → 유통 → (아시아) 소매 | ★ **유럽이 아시아에 치른 값 그 자체.** 방향이 반대인 유일한 갈래다 | 포토시 · 사도 · 나가사키 |
| **6** | **후추** | 생산 → **가공(건조·선별)** → 유통 → 소매 | 향신료 무역 **부피의 대부분**. 값이 가장 높지는 않았으나 물량이 가장 컸다 | 말라바르(캘리컷·크랑가노르) · 아체 |
| **7** | **도자기** | 생산 → **가공(요장)** → 유통 → 소매 | **유럽이 못 만들던 것.** 백자의 재현은 18세기에야 됐다 | 경덕진 배후 — 광저우 · 닝보 |
| **8** | **정향** ‡독점 | 생산 → 유통 → 소매 | **몰루카 다섯 섬에서만 났다** — 독점의 교과서 | 테르나테 · 티도레 |
| **9** | **육두구** ‡독점 | 생산 → 유통 → 소매 | **반다 제도에서만** | 반다 |
| **10** | **계피** ‡독점 | 생산 → 유통 → 소매 | **실론 왕실 독점** | 실론(콜롬보 · 갈레) |

### 1-6. ★ 지도가 사슬을 정한다

시설 조건(§2-6)이 `supply`/`demand`/`industry`를 그대로 읽으므로,
**한 항구에서 사슬을 다 돌릴 수 있는 자리는 거의 없다.**

- 사탕수수는 푼샬에서 나고 제당도 되지만(공업력 1) **설탕 수요는 북유럽**이다 → 유통이 필요하다
- 은광석은 포토시(공업력 **0**)에서 나고 **수은은 우앙카벨리카·말라가**다 → 두 산지를 물려야 한다
- 사라사는 **면포(구자라트) + 인디고(구자라트)**로 한 바다에서 완결되지만 **판로가 유럽**이다
- 주홍 모직은 **모직(플랑드르) + 코치닐(누에바에스파냐)** — **대서양을 한 번 건너야** 만들어진다
- 요장은 공업력 2를 요구하므로 A-2 부두 승급과 물린다

★ **수직계열화의 진짜 대가는 돈이 아니라 항로다.** 한 사슬을 완성하려면 그 사슬의 두세 항구를
되풀이해 들러야 하고, 그동안 아홉 바다의 다른 기회를 포기한다.
게임의 재미(**항구를 눌러 사고파는 것**)를 뺏지 않으면서 선택을 강요하는 자리가 여기다.

## 2. 시설

### 2-1. ★ 판단 — `HOLDINGS`에 얹지 않는다. 새 계층으로 간다

**결론: `state.works[cityId]`를 신설한다.** 근거 넷.

| # | 근거 |
|---|---|
| ① | **`HOLDINGS`는 종류가 다섯으로 고정된 불리언 집합**이다(`state.holdings[cityId][kind] = true`). 그런데 농장·판매소는 **품목마다 다르다** — 푼샬의 사탕수수 농장과 푼샬의 와인 농장은 다른 시설이다. `{kind, good, level, stock}`을 들어야 하므로 불리언으로는 못 담는다 |
| ② | **유지비 규칙이 다르다.** 거점은 매입가의 연 6%를 내고 못 내면 **즉시 압류**다. 시설은 사람이 붙어 더 무겁고(연 10%), 대신 **휴업**이라는 중간 단계가 있어야 한다 — 압류만 있으면 후반 한 번의 사고가 사슬 전체를 지운다 |
| ③ | **권역 패권 조건이 `holdings`를 센다**(`hegemonyOf`). 시설을 같은 그릇에 담으면 **패권 조건이 조용히 바뀐다.** `HEGEMONY` 주석이 *"조건을 무겁게 하면 벌금이 된다"*고 못박은 자리라 건드리면 안 된다 |
| ④ | **저장 비용이 0이다.** `save.js`가 `state`를 통째로 직렬화하므로 필드 하나가 느는 것뿐이다 |

**대신 두 계층을 못으로 잇는다** — **창고(`warehouse`) 없이는 어떤 시설도 못 짓는다.**
산출물을 둘 데가 있어야 하기 때문이고, 동시에 진입 문턱이 된다(창고는 `size × 8,000닢`).

⚠️ **이름 함정** — `state.industry`로 짓지 말 것. `city.industry`(공업력)와 `state.yards`(공업력 승급)가
이미 그 말을 쓰고 있어 셋이 뒤섞인다. **`state.works`**로 간다.

### 2-2. 자료구조

```js

   `works[cityId]`는 그 항구에 세운 시설의 모음이다. 키는 `<종>:<품목>`이라
   같은 항구에 사탕수수 농장과 목화 농장을 따로 둘 수 있다.
   ★ 전부 **평범한 객체**다(Set 금지) — `save.js`가 통째로 JSON으로 눕힌다. */
state.works = {
  funchal: {
    paid: 120,          // 마지막 유지비를 낸 날
    spent: 63711,       // 들인 돈 누계 — 유지비는 여기 붙는다
    'farm:cane':  { level: 2, since: 90, stock: 147, idle: false },
    'mill:sugar': { level: 2, since: 96, idle: false,
                    job: { recipe: 'refine_sugar', out: 30, until: 132 } },
  },

    paid: 120, spent: 24480,

                    consign: { sugar: 42 },   // 위탁해 둔 재고

  },
};

/* 정기 항로 — 동행선 하나를 A↔B에 묶는다 */
state.lines = {
```

### 2-3. ★ 가공마진 밴드 — 이 문서에서 가장 중요한 한 줄

```
1.08  ≤  (산출 기준가 × 산출 수량) ÷ Σ(투입 기준가 × 투입 수량)  ≤  1.25
가공비(현금) = 산출 기준가 합 × 0.10
```

- **밴드를 벗어나면 `check-chain.mjs`가 실패시킨다**(exit 1). 근거 없음이 아니라
  **규칙이 자기모순**인 경우라, 이 저장소가 정한 "실패 vs 경고"의 선에서 **실패** 쪽이다.
- **1.08이 하한인 이유** — 그 아래면 가공비 10%에 먹혀 **어떤 조건에서도 손해**가 되어 시설이 죽는다.
- **1.25가 상한인 이유** — 그 위면 §0-2의 정리가 깨진다. 곧 *"원료를 시세로 사서 가공해도 남는"*
  구간이 생기고, 그 순간 수직계열화는 **새 수입원**이 된다.

- 그 항구에서 그 품목을 살 때 **`stock`까지는 원가**, 그 위는 정상 시세다
- ★ **원가로 산 몫은 `addPressure`를 하지 않는다** — 자기 밭에서 실었기 때문이다
- 창고 칸을 먹지 않는다(밭에 서 있다). 대신 **45일 상한**이 규모를 묶는다
- 광산이 농장의 절반인 이유 — 광물은 값이 높아 같은 칸이 훨씬 큰 이득이기 때문이다

⚠️ **`costFor`가 두 구간을 갖게 된다.** 앞 `stock`칸은 원가·압력 면제, 나머지는 지금과 같다.
`buy()`의 이분 탐색은 **단조 증가**를 전제하는데 원가 < 시세이므로 단조는 유지된다 — 그러나
구현할 때 반드시 `test-rules.mjs`에 "원가 구간이 섞여도 `costFor(n)`이 단조인가"를 넣는다.

**가공장**

| level | 하루 처리(산출 칸 기준) | 착수 |
|---|---|---|
| 1 | 3칸 | 2일 |
| 2 | 5칸 | 2일 |
| 3 | 8칸 | 2일 |

- `소요 일수 = 2 + ceil(산출 수량 ÷ 하루 처리)`
- 투입 원료는 **착수할 때 창고에서 빠진다.** 산출은 완성일에 창고로 들어온다(창고가 차면 대기)
- 가공비(현금)는 착수할 때 낸다
- ★ **기다리는 것이 공짜가 아니다.** `waitDays()`(A-1b)가 이미 정박 급여·유지비를 물리므로
  가공을 기다리면 그 값을 낸다. 다시 오는 쪽을 골라도 되고, 그 선택이 이 시스템의 시계다

**판매소**

| level | 매도 압력 감쇠 | 위탁 소화 |
|---|---|---|
| 1 | −35% | 3칸/일 |
| 2 | −50% | 5칸/일 |
| 3 | −65% | 8칸/일 |

- **팔 때만** 감쇠한다(`addPressure(city, good, n × (1 − shopCut))`). 살 때는 감쇠하지 않는다 —
  소매는 파는 자리이고, 양방향으로 깎으면 같은 항구에서 사고팔기를 되풀이하는 무한 루프가 열린다
- **위탁 판매** — 창고 재고를 판매소에 넘기면 하루 3~8칸씩 그날 시세로 팔린다. **수수료 12%** + 관세는 그대로
- ★ **정산은 그 항구에 들를 때** 한 번에 한다. 금고로 자동 입금하지 않는다 — §3-1 경계

> ★ 판매소가 파는 것은 **마진이 아니라 시장 깊이**다. 320칸짜리 배로 한 항구에 쏟으면
> `MARKET.cap 0.50`에 닿는데, 판매소는 그 벌점을 **시간으로 바꾼다.** 값을 시간으로 사는 것이다.

### 2-6. 지을 수 있는 조건

| 시설 | 조건 |
|---|---|
| 공통 | 그 항구에 **창고(`warehouse`) 이상** · 그 자리의 임자 판정(§5)을 통과 |
| `farm` | 그 도시 `supply[good]`이 있고, 그 품목이 **작물류**(`GOODS[].kind === 'crop'`) |
| `mine` | 그 도시 `supply[good]`이 있고, 그 품목이 **광물류**(`kind === 'mineral'`) |
| `mill` | 그 도시 `industry ≥ recipe.req` · **한 항구에 가공장은 셋까지** |
| `shop` | 그 도시 `demand[good]`이 있어야 한다 |
| 상한 | 한 항구에 시설 **여섯까지** |

⚠️ **`GOODS`에 `kind` 태그를 붙여야 한다** — `crop` / `mineral` / `craft` / `other`.
83 + 7 = 90종에 한 줄씩. 없으면 "은광석 농장" 같은 것이 지어진다.
태그는 그 품목을 정의한 `js/regions/<권역>/goods.js`에 적는다(권역이 정본이라는 규약 유지).

### 2-7. 유지비 · 휴업 · 압류

| 규칙 | 값 | 거점(A-1)과의 차이 |
|---|---|---|
| 유지비 | `works[city].spent`의 **연 10%**를 30일마다 | 거점은 6% — 시설은 사람이 붙어 더 무겁다 |
| 청구 | 그 항구에 **들어올 때**(`settleWorks`) | 거점과 같은 리듬 |
| 못 내면 | **① 휴업(`idle: true`)** — 산출 0, 가공 정지, 위탁 판매 정지. 유지비는 **절반**만 문다 | 거점은 곧바로 압류 |
| 두 번 연속 못 내면 | **② 압류** — 그 항구 `works` 전부 + 그곳 `stored` 화물이 넘어간다 | 거점과 같다 |
| 되살리기 | 밀린 유지비를 내면 다음 날부터 다시 돈다 | — |
| 매각 | 들인 돈의 **60%** | 거점에는 매각이 없다(⇒ §9-①) |
| **몰수** | **그 세력과 전쟁 상태가 되면 그 세력 항구의 내 시설이 넘어간다**(§5-5) | 거점에도 같은 판정을 얹을지는 §9-① |

★ **휴업을 넣은 이유** — 사슬은 여러 항구에 걸치므로 한 항구의 사고로 전체가 끊기면
"수직계열화"가 도박이 된다. 대신 휴업 중에도 **절반은 나가므로** 방치가 답이 되지는 않는다.

★ **패권 조건은 건드리지 않는다.** `hegemonyOf`는 `state.holdings`만 센다.
시설을 조건에 넣으면 *"조건이 아니라 벌금"*이 된다(`HEGEMONY` 주석).

## 3. 유통 라인

### 3-1. ★ 경계 — **유통 라인은 사고팔지 않는다**

> **정기선도 위탁도 짐을 옮기기만 한다. 매매는 항구에서 플레이어가 누른다.**

이 게임의 재미는 **항구를 눌러 사고파는 데** 있다. 자동으로 시세를 보고 사고파는 창구를 만들면
최적 플레이가 *"항로를 걸어 놓고 지켜본다"*가 되고, 그 순간 게임의 몸통이 사라진다.
동시에 그것은 **새 수입원**이라 §0의 원칙에도 걸린다.

| 자동화가 하는 것 | 자동화가 **절대 안 하는 것** |
|---|---|
| 창고 A의 짐을 창고 B로 옮긴다 | 시세를 보고 산다 |
| 농장 재고를 가공장으로 옮긴다 | 시세를 보고 판다 |
| 해적·폭풍 판정을 받는다 | 계약을 맡는다 |
| 급여·보급·유지비를 문다 | 배를 사거나 판다 |
| 결과를 **항해일지에 남긴다** | 금고에 돈을 넣는다 |

★ **판매소의 위탁 판매만이 유일하게 "파는" 자동화**이고, 그것도 ①이미 산 물건을
②수수료 12%를 물고 ③하루 3~8칸씩만 ④**그 항구에 들러야 정산된다.**
곧 자동화가 아니라 **느린 매도 창구**다.

### 3-2. (ㄱ) 정기선 — 동행선 하나를 항로에 묶는다

`state.lines` · `data.js: LINE`

| 항목 | 값 | 왜 |
|---|---|---|
| 배정 | `state.consorts`의 동행선 1척을 뺀다 | ★ **이것이 값이다** — 화물칸(`cargoCapTotal`)·포화력(`consortGuns`)·피해 분산(`shieldPer`)을 잃는다 |
| 동시 상한 | **3선** | 동행 8척 중 셋까지. 넷을 넘기면 선단이 사라진다 |
| 왕복 주기 | `voyageDays(a,b) × 2 + 4`일 | 하역 이틀씩 |
| 적재 | 그 배 `cargo` × **0.70** | 최소 인원만 태우므로 다 못 싣는다 |
| 인원 | `crewMin × 1.0` (`FLEET.crewRate`와 같다) | 급여는 `state.payroll`에 **그대로** 쌓인다 |
| 유지비 | 선체·무장·선단 유지비를 매일. 보급은 **정박선의 2배**(늘 바다에 있다) | 성장할수록 무거워지는 갈래를 그대로 승계 |
| 나르는 품목 | **최대 3종**, 창고→창고 이동만 | §3-1 |
| 해적 | 편도마다 `ROUTE_RISK`로 판정 → 걸리면 **짐 전량 유실**, 그중 **15%는 배까지 잃는다** | 배를 잃는 규칙이 이 게임에 이미 있다(`spreadDamage`) |
| **세력 나포** | ★ 적대 세력의 사냥 구간을 지나면 **그 세력이 나포한다**(§5-5) | 「전쟁」이 유통에 닿는 자리 |
| 보험 | 켜면 편도마다 `화물시가 × 요율 × INSURANCE_RATE`. 유실 시 **30% 보상**(`INSURANCE_COVER`) | 기존 상수를 그대로 쓴다 |
| 해산 | 언제든. 배는 그 시점에 있던 항구에 정박한다 | — |
| 보고 | 왕복마다 **항해일지에 한 줄**. 플레이어가 그 항구에 들를 때 읽는다 | 화면 밖으로 밀어내지 않는다 |

⚠️ **`tickLines(n)`은 `advanceDays()`와 `waitDays()` 양쪽에서 불러야 한다.**
한쪽만 걸면 *"항구에 서 있는 동안 정기선이 멈춘다"*(또는 그 반대)가 된다.
`QUICKMAP-trade.md` §3의 *"항구에는 시간이 없다"*가 이제 절반만 참이라는 것을 잊기 쉽다.

### 3-3. (ㄴ) 위탁 — 남의 배에 실어 보낸다

`state.consign`. 배를 묶지 않는 대신 비싸고 위험하다.

| 항목 | 값 |
|---|---|
| 조건 | 보내는 곳·받는 곳 **양쪽에 창고 이상** |
| 수수료 | `화물 시가 × (0.06 + 그 항로 요율)` — 요율 2~9%라 총 8~15% |
| 일수 | `voyageDays × 1.4` (남의 배는 제 일정으로 다닌다) |
| 유실 | 확률 `ROUTE_RISK% × 0.5` — 걸리면 **전량**. 배가 아니라 짐만 잃는다 |
| ★ 세력 | **위탁은 남의 배다** — 적대 세력의 배에는 못 싣는다(그 세력이 그 항로를 쥐고 있으면 위탁 자체가 막힌다) |
| 보험 | 켜면 수수료 ×2, 유실 시 시가의 **30%** |
| 상한 | 한 건에 **40칸** · 동시 **5건** |

★ **초반의 문**이다. 정기선은 동행선을 하나 빼야 하므로 A-4 선단이 자란 뒤에나 성립하는데,
위탁은 창고 둘만 있으면 된다. 대신 **수수료 8~15%가 항차 ROI 중앙값(10.1%)과 맞먹어**
"급할 때만 쓰는 길"이 된다.

### 3-4. 왜 둘 다인가

| | 정기선 | 위탁 |
|---|---|---|
| 진입 문턱 | 높다(배 한 척 + 선원) | 낮다(창고 둘) |
| 회당 값 | 싸다(유지비만) | 비싸다(8~15%) |
| 위험 | 배까지 잃을 수 있다 | 짐만 잃는다 |
| 세력 | 내 배라 적대해도 다닌다(대신 나포당한다) | **적대하면 아예 못 쓴다** |
| 무엇을 파나 | **선단의 전투력과 화물칸** | **마진** |
| 언제 쓰나 | 사슬이 굳은 뒤, 같은 구간을 되풀이할 때 | 한 번만 옮길 때 · 급할 때 |

곧 **같은 문제에 대한 값이 다른 두 답**이다. 하나만 두면 후반 전용(정기선)이거나
영원히 손해(위탁)가 되어 선택이 사라진다.

## 5. 세력 — 경쟁과 전쟁

> 사용자 지시: *"당연히 다른 상단, 제노바, 동인도 회사 등 **그 당시 세력들과도 경쟁하고 때로는 전쟁**해야겠지."*
>
> ★ **이 사슬은 비어 있는 땅이 아니다.** 열 갈래는 전부 16세기에 임자가 있었고,
> 그 임자가 누구였는지가 곧 그 세기의 역사다. 아래 §5-2 표는 **`SPEC-factions.md`의 입력**이다 —
> 세력의 성격·함대·평판 곡선은 그쪽이 정본이고, 이 문서는 **사슬의 어느 칸이 누구 밥그릇인가**만 정한다.

### 5-1. 자리의 세 등급 (`claim`)

시설을 세우려는 (도시 × 품목 × 층) 자리마다 등급이 하나 붙는다.

| 등급 | 뜻 | 지을 때 | 그 뒤 |
|---|---|---|---|
| `open` | 임자 없음 | 정가 | — |
| **`held`** (점유) | 그 세력이 이미 그 자리를 쥐고 있다 | **값 ×1.6~2.2** (세력 규모에 비례) | 그 세력 `standing` **−12** · 그 세력 항구 입항세 **+1.5%p** · 내 시설 산출 **−20%**(점유율을 나눈다) |
| **`monopoly`** (독점) | 칙허·조약으로 막았다 | **살 수 없다** | 아래 세 길 |

**독점을 여는 세 길**

| 길 | 값 | 대가 |
|---|---|---|
| **① 면허** | 시설값 × **3.0**을 그 세력에 낸다 + 산출의 **15%를 상납**(영구) | 돈이 가장 많이 들지만 관계가 안 상한다. `state.factions[f].licenses[good] = true` |
| **② 밀조** | 시설값 × 1.4 (뒷돈) | 입항할 때마다 **적발 판정**(기본 12% · 악명과 함께 오른다). 걸리면 **시설 몰수 + 그 항구 `stored` 몰수 + `standing` −30**. 그 세력의 사냥 확률이 오른다 |
| **③ 전쟁** | 그 항구의 세력 함대(등급 4~5)를 꺾는다 — `state.slain`에 기록 | 그 세력과 **전쟁 상태**(`atWar`)가 된다. §5-5 |

★ **이것이 방어 ⑦이다.** 가장 값나가는 셋(정향 680 · 육두구 760 · 계피 300)은
**돈만으로는 절대 안 열린다.** 면허를 사면 산출의 15%가 영구히 새고,
밀조하면 언제 다 잃을지 모르고, 전쟁하면 그 바다 전체가 적이 된다.
곧 **가장 큰 이문에는 가장 큰 값이 붙어 있다** — 사료가 그랬듯이.

### 5-3. 평판 (`standing`)

`state.factions[f].standing` — **−100 ~ +100**. 기존 `state.infamy`(깃발별 악명)와 **다른 축**이다.
악명은 *"상선을 털었나"*이고 평판은 *"그 세력의 사업을 밟았나"*다. 둘은 서로를 밀어 준다.

| 값 | 이름 | 그 세력 항구에서 |
|---|---|---|
| +40 이상 | 협력 | 면허값 −25% · 그 세력 항로에서 위탁 수수료 −3%p |
| +10 ~ +39 | 우호 | 입항세 −0.5%p |
| −9 ~ +9 | 중립 | — |
| −10 ~ −39 | 냉담 | 그 자리 값 +20% · **위탁을 못 쓴다** |
| −40 ~ −69 | 적대 | 그 세력 항구 입항세 +3%p · **정기선 나포 판정**(편도 8%) |
| −70 이하 | **전쟁**(`atWar`) | §5-5 |

**평판이 오르내리는 자리**

| 사건 | 값 |
|---|---|
| `held` 자리에 시설을 세운다 | −12 |
| 밀조가 적발된다 | −30 |
| 그 세력 함대를 꺾는다 | −25 (그리고 `state.infamy` 그 깃발 +) |
| 면허를 산다 | +8 |
| 그 세력 항구에서 대형 주문(계약)을 마친다 | +4 |
| 그 세력의 적을 꺾는다 | +6 |
| **아무것도 안 한 채 40일** | 0 쪽으로 **1칸** (`INFAMY.decayDays`와 같은 리듬) |

### 5-4. 경쟁 — 같은 자리에 둘이 서면

- 같은 도시·품목에 세력 시설이 있으면 **내 시설 산출 −20%**(점유율을 나눈다)
- 반대로 내 시설이 서면 **그 도시의 그 품목 `supply` 배율이 0.03 얕아진다** — 시장에 물건이 늘어난 것이다
  ★ 이것이 유일하게 **세계 시세를 움직이는** 자리다. 곧 **내가 크게 만들수록 내 이문이 얇아진다** —
  독점을 깨는 자가 스스로 값을 떨어뜨리는 구조이고, 실제 후추값이 그렇게 무너졌다
- 세력이 **되받아친다** — `standing`이 −10 아래면 그 세력이 같은 도시에 시설을 하나 더 세운다(30일 판정, 확률 20%)

### 5-5. 전쟁 (`atWar`)

`standing ≤ −70`이 되면 그 세력과 전쟁 상태가 된다.

| 무엇이 | 어떻게 |
|---|---|
| **입항** | 그 세력 항구에 **못 들어간다**(중립 항구는 그대로) |
| **시설** | 그 세력 항구의 내 `works`와 `stored`가 **몰수된다** — 전쟁이 선언된 날 |
| **정기선** | 그 세력 사냥 구간에서 편도 **20%** 나포 판정 |
| **위탁** | 못 쓴다 |
| **해상** | 그 세력 함대가 나를 **찾아온다**(`world.js`의 해적 사냥 배선을 그대로 쓴다) |
| **끝내기** | ① 배상금(몰수당한 시설값의 2배)을 내고 `standing`을 −40으로 ② 그 세력의 기함(등급 5)을 꺾어 −50으로 |

★ **전쟁은 이득이 아니라 사고다.** 이기면 독점 하나가 열리지만 그 바다의 항구 절반을 잃는다.
그래서 *"때로는 전쟁"*이지 *"전쟁이 최적해"*가 아니다 —
`sim-chain.mjs`가 **전쟁을 고르는 판이 20판 중 3판을 넘으면** 값이 틀린 것이다(§6-3).

### 5-6. 무엇을 이 문서가 정하지 **않는가**

`SPEC-factions.md`가 정할 것 — 세력의 함대 구성·등급 · 항구 소유 목록 · 시대에 따른 교체
(포르투갈 → VOC) · 세력끼리의 관계 · 세력 인물(`npc-figures.js`와의 배선) ·
전쟁 연출 · 그리고 **세력이 실제로 배를 몰고 다니는가**(`world.js` 확장 여부).

이 문서가 정한 것은 **사슬의 어느 칸이 누구 것인가**(§5-2)와
**그것이 시설 값·산출·평판에 어떻게 물리는가**(§5-1·§5-3·§5-4)뿐이다.

## 6. 밸런스 검증

### 6-1. ★ 곡선이 나쁘면 **시뮬의 플레이 전략부터** 의심한다

이 저장소의 교훈이고, 이 사양에서 가장 걸리기 쉬운 함정이다.

- 실제 사례 — *"선체 60% 미만이면 전액 수리"*가 누수 2pt/일짜리 시작배에 걸려 하루 28닢을 태웠고,
  20판 중 18판이 배를 한 척도 못 샀다. **게임은 멀쩡했다.**
- 사슬에서 같은 일이 일어날 자리:
  - **농장 재고를 무시하고 매 항차 시세로 원료를 산다** → 사슬이 언제나 손해로 나온다(§0-2 정리대로)
  - **가공 완료를 기다리지 않고 떠난다** → 산출을 영영 못 받는다
  - **회수기간을 못 보고 20항차에 정향 농장을 노린다** → 파산
  - **판매소 압력 감쇠를 `planFor`가 모른다** → 대형선의 이득이 통째로 안 잡힌다
  - **`held` 웃돈을 안 보고 최저가 자리만 고른다** → 평판이 −70까지 미끄러져 판이 죽는다
- ⇒ `sim-core.mjs`의 사슬 전략은 **의도적으로 보수적으로** 짠다(§6-2).

### 6-2. `sim-core.mjs`에 무엇을 더하나

`runSim({ chain })`에 스위치를 넣는다. **`chain: false`가 기본**이라 기존 도구는 안 움직인다.

| 값 | 뜻 |
|---|---|
| `false` | 지금과 똑같다 (기준선) |
| `'basic'` | 가공장만 쓴다 (1단계 검증) |
| `'full'` | 생산·가공·소매·유통을 전부 쓴다 |
| `'full+war'` | 위에 더해 **독점을 깨는 길**(면허·밀조·전쟁)까지 고른다 |

**「짓는 규칙」 (시뮬의 플레이 전략 — 사람이 할 만한 것으로)**

```
① 금고가 (시설값 × 2.5 + 30일 고정비 × 3)을 넘을 때만 짓는다
② 그 항구를 최근 60일에 **두 번 이상** 들렀을 때만 짓는다      ← 항로가 굳었다는 뜻
③ 사슬은 머리부터 — 농장 → 가공장 → (창고) → 판매소 순
④ 원료는 **농장 재고를 다 쓴 뒤에만** 시세로 보탠다
⑤ 가공 완료일이 다음 입항 예정일보다 늦으면 착수하지 않는다
⑥ 30일 순이익이 두 주기 연속 고정비를 못 넘으면 **매각한다**
⑦ `standing`이 −35 아래인 세력의 `held` 자리는 고르지 않는다   ← 전쟁을 피한다
⑧ 독점은 **면허를 살 돈이 있을 때만** 연다. 밀조는 `standing ≥ 0`일 때만
```

**측정 지표** — 금화가 아니라 **총자산**이다.
`총자산 = 금고 + 선단 매각가 + 시설 매각가(60%) + 창고 재고 시가 + 실은 짐 시가`
(금화만 보면 *"방금 시설을 샀는가"*에 지배된다 — 부관 측정에서 배운 것과 같은 함정)

**짝지어(paired) 잰다.** 같은 시드로 `chain:false`와 `chain:'full'`을 한 번씩.
따로 20판씩 돌려 비교하면 기준선이 25%씩 튀어 **효과의 부호가 뒤집힌다**(부관에서 실제로 겪었다).

### 6-3. 합격 · 기각선

새 도구 **`node tools/sim-chain.mjs [판수]`** (기본 20 · paired)

| 지표 | 기준선 | **합격 범위** | 기각 |
|---|---|---|---|
| 30항차 총자산 중앙값 | 측정값 X | **X × 0.95 ~ 1.15** | > ×1.20 |
| 60항차 총자산 중앙값 | 측정값 Y | **Y × 0.95 ~ 1.20** | > ×1.25 |
| 항차 ROI 중앙값 | 10.1% | **8 ~ 13%** | > 15% |
| **고정비 ÷ 총지출** | 측정값 | **+8%p 이상 올라야 한다** | 안 오르면 목적 미달 |
| 첫 시설을 짓는 항차 | — | **20항차 이후** | 12항차 이전이면 값이 싸다 |
| 완주(60항차) 판 | 20/20 | **18~20/20** | < 17이면 고정비가 과하다 |
| 시설 압류·몰수를 겪은 판 | — | **1~5/20** | 0이면 고정비·세력이 무의미하다 |
| 사슬 자본 연수익률 | — | **25 ~ 45%** | > 60%면 §0-2가 깨졌다 |
| **전쟁을 고른 판** | — | **0~3/20** | > 5면 전쟁이 최적해가 됐다 |
| **독점 열린 갈래 수**(60항차) | — | **0~2갈래** | 3 이상이면 독점이 장식이다 |

> ★ **두 방향으로 다 기각된다.** 총자산이 ×1.20을 넘으면 새 수입원을 만든 것이고,
> 고정비 비중이 안 오르면 *"덜 잃고 더 크게 굴린다"*를 못 이룬 것이다.
> **곡선이 그대로이고 고정비만 오르는 것이 성공**이다.

★ **1단계(가공장만)의 합격선은 더 좁다 — 기준선 대비 ±5%.** 사슬만으로는 §0-2에 따라
거의 안 남는 것이 정상이고, 5%를 넘게 움직이면 §2-3 밴드나 가공비가 틀린 것이다.

### 6-4. `tools/check-chain.mjs` — 근거 검증 (신설)

⚠️ **실패와 경고의 선을 지킨다** — 이 저장소의 규약대로 *"근거 없음"으로는 실패시키지 않는다.*

| # | 검사 | 판정 |
|---|---|---|
| ① | `CHAIN`의 모든 투입·산출 id가 `GOODS`에 있나 | **실패** |
| ② | 가공마진이 밴드 `[1.08, 1.25]` 안인가 | **실패** |
| ②-b | `사슬 조달가 ÷ 최저 산지 시세 ∈ [0.95, 1.10]`인가 | **경고** (§1-5) |
| ③ | 사슬 그래프에 **순환**이 없나 (A→B→A) | **실패** |
| ④ | 모든 시설이 지어질 수 있는 도시가 실제로 하나 이상 있나(`supply`/`demand`/`industry` 대조) | **실패** — 없으면 그 사슬은 죽은 규칙이다 |
| ⑤ | **`monopoly`·`held` 자리가 실제 도시 id를 가리키나** | **실패** — 유령 자리 |
| ⑥ | 새 품목이 `content/goods-evidence.json`에 있나 | **경고** |
| ⑦ | 모든 가공품에 산지 ≥ 1 · 수요지 ≥ 3 | **경고** |
| ⑧ | `GOODS[].kind` 태그가 90종 전부에 있나 | **경고** |

**기존 도구 확장**

- `check-prices.mjs` — 새 품목 7종의 **곡물 대비 비율**을 밴드로 본다(경고)
- `check-evidence.mjs` — 신규 `supply`/`demand`가 권역 근거 JSON과 맞는가 (기존 규칙 그대로)
- `check-architecture.mjs` — `state.works` · `state.lines` · `state.consign` · `state.factions` 네 필드 (자동으로 잡는다)
- `test-rules.mjs` — **원가 구간이 섞여도 `costFor(n)`이 단조 증가인가**(§2-5 함정)
- `test-payroll.mjs` — 정기선 급여가 `state.payroll`에 실제로 쌓이는가 · **장부 갈래가 늘 때 금고와 안 어긋나는가**

### 6-5. 대시보드

**새 탭을 만들지 않는다.** 「경제」 탭에 절 하나(**사슬**)를 얹는다 —
파일을 안 늘리면 `check-architecture` 부담도 없다.

| 보여줄 것 | 왜 |
|---|---|
| 열 갈래의 **마진 밴드 막대** | 밴드를 벗어난 갈래가 한눈에 보인다 |
| 갈래마다 **사슬 조달가 vs 최저 산지 시세** | §0-2 정리가 지금도 참인지 |
| 갈래마다 **지을 수 있는 도시 수 · 임자 등급 분포** | 죽은 사슬과 「전부 독점」인 사슬을 잡는다 |
| 시설 종류별 **회수기간 · 자본 연수익률** | §0-4의 값이 코드에서 실제로 나오는지 |

## 7. 단계적 구현 순서

### ★ 1단계 — **직물 세 갈래.** 가공장만 · 세력 0

**왜 직물인가** — 열 갈래 가운데 **원료가 이미 게임에 다 있는 것이 직물 계열뿐**이다.
`cotton` · `calico` · `wool` · `woolcloth` · `indigo` · `cochineal`이 전부 실재하고,
새로 만들 것은 **산출 둘(`chintz` · `scarlet`)**뿐이다. 곧 **가장 적은 데이터로 사슬이 서는 자리**이고,
사용자가 지목한 본보기 넷 가운데 **둘(면포·염료)**이 여기 들어 있다.

| | |
|---|---|
| 넣는 것 | `CHAIN` **3갈래** — 방직(`cotton 3 → calico 2`) · 날염(`calico 2 + indigo 1 → chintz 2`) · 주홍(`woolcloth 2 + cochineal 1 → scarlet 2`) |
| 시설 | **가공장(`mill`)만.** 창고 선행 · `state.works` 신설 |
| 화면 | 항구 「거점」 카드 아래에 「가공장」 한 줄 |
| 새 품목 | **2개** — `chintz 320` · `scarlet 510` (산지 1~2곳 · 수요 4~8곳) |
| 안 넣는 것 | 농장·광산 · 판매소 · 유통 · 세력 · 나머지 일곱 갈래 |
| 근거 | `content/chain-evidence.json` 신설(3갈래분) · `goods-evidence.json` 2종 |
| 검증 | `check-chain.mjs` ①②③④⑦ · `sim-chain.mjs 'basic'`으로 **±5% 안** 확인 |

★ **이것만으로 성립하는가 — 성립한다.** 그리고 **2단 사슬이 처음부터 보인다** —
원면 → 면포 → 사라사. *"어디서 원료가 싼가"*와 *"어디까지 가공해서 팔 것인가"*를
동시에 묻는 판이 이 세 갈래로 완성된다.
게다가 **`cotton`(산지 1곳·수요 1곳)과 `wool`(5/2)이라는 죽어 있던 두 품목이 살아난다.**

### 2단계 — **생산 + 남은 새 품목 5종 + 열 갈래 완성**

| | |
|---|---|
| 넣는 것 | 농장·광산 · **남은 새 품목 5종**(`cane`·`rawsilk`·`silverore`·`rawpepper`·`kaolin`) · `GOODS[].kind` 태그 90종 · 사슬 일곱 완성 · 독점 아닌 갈래 전부 |
| 왜 여기서 | **농장이 붙어야 사슬이 실제로 남는다**(§0-2). 곡선이 처음 움직이는 단계라 여기서 §6-3을 정면으로 재야 한다 |
| 함께 갈 것 | `content/goods-evidence.json` 5종 · 권역 근거 JSON의 새 `supply`/`demand` · 아이콘 빌림 표 |
| 검증 | `sim-chain.mjs 'full'` 전 지표 · `check-prices.mjs` 확장 · 대시보드 「사슬」 절 |

### 3단계 — **소매 + 유통**

| | |
|---|---|
| 넣는 것 | 판매소(`shop`) · 위탁(`consign`) · 정기선(`state.lines`) |
| 왜 여기서 | 판매소는 `impact` 감쇠라 **대형선이 있어야 의미가 있고**, 정기선은 A-4 선단(2026-08-23 구현)에서 동행선을 빼는 것이라 그것이 먼저다 |
| 함정 | `tickLines`를 `advanceDays`·`waitDays` **양쪽**에 배선(§3-2) |
| 검증 | `sim-chain.mjs 'full'` · 항해일지에 정기선 보고가 실제로 뜨는지 실클릭 |

### 4단계 — **세력 (경쟁과 전쟁)** ★ `SPEC-factions.md`와 함께

| | |
|---|---|
| 넣는 것 | `state.factions` · `claim` 세 등급 · 면허/밀조/전쟁 세 길 · `standing` 곡선 · 몰수 |
| 왜 마지막인가 | 세력은 **사슬 위에 얹히는 층**이다. 사슬이 서 있지 않으면 *"누구 밥그릇"*이 성립하지 않는다. 그리고 세력 자체(함대·항구·인물)는 `SPEC-factions.md`가 먼저 서야 한다 |
| ⚠️ | **여기서 곡선이 두 번째로 크게 움직인다** — 독점이 열리면 정향·육두구가 사슬로 들어오기 때문이다. `sim-chain.mjs 'full+war'`로 다시 잰다 |
| 검증 | §6-3의 「전쟁을 고른 판」·「독점 열린 갈래 수」 두 줄 |

### 5단계(선택) — **표시만**

한 권역에서 네 층을 다 갖추면 「**일관(一貫)**」 표시.
★ **보상은 없다.** `HEGEMONY`와 같은 규약이다 — 얻는 것은 이미 시설이 주던 것뿐이고,
늘어난 고정비가 그 목표의 값이다. **패권 조건에는 넣지 않는다.**

| **⑤** | **밀무역(N6)·등록(registro)과 §5 밀조** | 같은 자리다. N6 사양이 나오면 **하나로 합친다** — 두 개의 적발 판정을 만들면 안 된다 |
| **⑥** | **세력이 실제로 배를 몰고 다니는가** | `SPEC-factions.md`가 정한다. 이 문서는 「사냥 확률」이라는 숫자로만 닿는다 |
| **⑦** | **사슬 완성을 엔딩 조건으로** | **넣지 않는다.** 끝이 둘(`ENDING`·`HEGEMONY`)인 것이 밸런스 회귀를 막고 있다. 셋째를 만들면 그 전제가 깨진다 |

## 10. 값의 출처 — 근거 / 밸런스 갈라 적기

이 저장소의 규약이다. **근거가 있는 값과 밸런스로 정한 값을 섞어 적지 않는다.**

### 10-1. 사료 근거가 있는 것

| 값 | 근거 |
|---|---|
| **열 갈래의 선정** | 사용자 기준(*"유럽에서 가장 가치가 큰 것"*)을 16세기 수입 결제 흐름으로 옮긴 것 — 향신료 넷(후추·정향·육두구·계피) · 직물 셋(비단·면포·염료) · 설탕 · 도자기 · 은 |
| 사슬 **투입:산출 비율의 방향** | 원면→면포 무게 손실 ~35% · 양모→모직 손실 큼 · 사탕수수 즙이 산지에서 졸여진 것 · 후추를 데쳐 말리면 무게가 절반 아래 · 포토시 광석 품위(광석 8짐에 은 1짐) · 고령토와 백돈자의 배합 |
| **수은이 은 정련에 든다** | 아말감법(patio process). 게임에 `mercury`가 이미 있고 산지가 말라가·우앙카벨리카다 |
| 새 품목의 **기준가 순서** | 곡물 대비 비율 — 생사가 비단의 약 절반 · 날염포가 흰 면포의 서너 배 · *scarlatto*가 유럽 직물 최고가 |
| 시설 값의 **자릿수** | `asset-evidence.json` — 도시 연립주택 3,000~4,000두카트(선원 연봉 150~200배) · 대운하 궁전 200,000두카트 |
| 정기선·위탁의 **위험** | `ROUTE_RISK`(당대 해상보험 요율 2~9%)를 그대로 쓴다. 새 위험 축을 만들지 않았다 |
| **§5-2 임자 표 전부** | 카레이라 다 인디아 · 카르타스 · 카사 데 콘트라타시온 · 킨토 · 우앙카벨리카 왕실 독점 · 마카오–나가사키 항해권 경매 · 실론 계피 왕실 독점 · VOC의 반다·몰루카 독점 · 경덕진 관요 · 구자라트 바니아 — **전부 실재한 제도**다 |
| **내가 크게 만들수록 값이 떨어진다**(§5-4) | 후추값이 실제로 그렇게 무너졌다. 독점을 깬 자가 스스로 이문을 깎는다 |

### 10-2. 밸런스로 정한 것 (사료가 말하지 않는다)

| 값 | 왜 그 값인가 |
|---|---|
| **가공마진 밴드 1.08~1.25** | §0-2의 정리가 성립하는 폭. 하한은 시설이 안 죽을 만큼, 상한은 *"시세로 사서 가공해도 남는"* 구간이 안 생길 만큼 |
| **가공비 = 산출가 × 0.10** | 밴드의 절반을 먹게 정했다. 이 하나로 §0-2의 3~5% 손해가 만들어진다 |
| 정확한 투입 수량(7:1, 15:2, 3:2, 5:3, 4:1 …) | **비율의 방향만 사료이고 정수는 밴드에서 역산**했다. 그래서 새 품목의 `base`도 역산값이다 |
| 시설 값 공식의 계수(50 · 80 · 22 · TIER_MUL) | §0-4의 회수기간이 300일을 넘고 자본 연수익률이 25~45%에 들도록 |
| 유지비 **연 10%** | 거점 6% 위에 얹되 *"사람이 붙는다"*가 설명이 되는 폭. §6-3의 「고정비 비중 +8%p」가 판정한다 |
| 원가 절감 **12/18/24%** · 산출 4·7·10칸 · 재고 상한 45일치 | 대형선 320칸을 원가로 못 채우게 하는 상한. **방어 ③의 몸통이다** |
| 판매소 감쇠 35/50/65% · 위탁 수수료 12% | `MARKET.cap 0.50`을 완전히 지우지 않는 폭(최대 감쇠에도 0.175는 남는다) |
| 정기선 적재 0.70 · 동시 3선 · 격침 15% | 선단(`FLEET.max 8`)에서 셋을 빼도 전투가 성립하는 선 |
| 위탁 수수료 `0.06 + 요율` | 항차 ROI 중앙값 10.1%와 맞먹게 — *"급할 때만 쓰는 길"* |
| 매각 회수율 **60%** | 잘못 지으면 아프되 재기는 되는 폭 |
| **`held` 웃돈 ×1.6~2.2 · 면허 ×3.0 + 상납 15% · 밀조 ×1.4 + 적발 12%** | 셋의 기대비용이 비슷하되 **성격이 다르게** — 면허는 확실히 비싸고, 밀조는 싸지만 분산이 크고, 전쟁은 공짜지만 판을 흔든다 |
| `standing` 여섯 구간과 문턱(−10 / −40 / −70) | `INFAMY`와 같은 리듬(40일에 한 칸 회복)으로 맞췄다. 두 축이 따로 놀면 플레이어가 못 읽는다 |
| 시설 상한(한 항구 여섯 · 가공장 셋) | 한 항구가 세계를 다 하지 못하게 (§1-6) |

### 10-3. 사료를 의도적으로 덮어쓴 것 (`verdict: "gameplay"`)

| 값 | 왜 |
|---|---|
| **열 세력이 한 지도에 공존한다** | VOC(17세기)와 베네치아 향신료 전성기(15세기)는 실제로 겹치지 않는다. **연도를 고정하지 않는다**는 최상위 지침 그대로 — 기사단령 로도스와 몰타를 둘 다 둔 것과 같은 판단이다 |
| `kaolin` 28닢 (곡물 ×1.4) | 실제로 고령토는 교역품이라기보다 관요의 원료였다. **요장 사슬을 성립시키려고** 교역품으로 세운다 |
| `scarlet` 510닢 (곡물 ×25.5) | 유럽 직물이 아시아 최고급품(비단 420)보다 비싸진다. *scarlatto* 값이 실제로 그랬으나, 게임의 「유럽이 사는 쪽」 구도를 한 칸 흔든다 |
| 독점을 **전투로** 열 수 있다 | 실제로는 조약·학살·수십 년이 걸렸다. 게임에는 한 판의 전투로 압축한다 — 대신 §5-5의 대가를 무겁게 뒀다 |

## 11. 금지 사항 (원칙 승계)

- **새 수입원을 만들지 않는다.** 시설은 *"덜 잃고 더 크게 굴리는"* 장치이고, 그 증거는 §6-3의 수치다
- **자동화가 플레이어를 화면 밖으로 밀어내지 않는다.** 유통은 옮기기만 한다(§3-1)
- **패권·엔딩 조건을 건드리지 않는다.** 조건이 무거워지면 목표가 아니라 벌금이 된다
- **검증기가 콘텐츠를 억제하지 않는다.** 실패는 *코드와 근거가 어긋난 것*뿐이고 미조사는 경고다(§6-4)
- **연도를 못 박지 않는다.** 세력의 근거도 *"몇 년에 누가"*가 아니라 *"어떤 제도로 무엇을 쥐었나"*로 적는다
- **품목을 함부로 넓히지 않는다.** 사용자가 *"너무 확장하진 말고"*라고 못박았다 — §9-③이 그 대기열이다
- **곡선이 나쁘면 게임보다 `sim-core.mjs`의 플레이 전략을 먼저 의심한다**(§6-1)
