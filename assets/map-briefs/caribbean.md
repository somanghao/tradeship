# 카리브·누에바에스파냐 지도 제작 의뢰서

**tradeship — 대항해시대 교역 게임** / 2D 픽셀아트 항해 지도 1장 / 400×225 PNG

이 문서 하나만 읽고 작업할 수 있게 썼습니다. 게임 코드를 볼 필요는 없습니다.
이 게임의 바다는 아홉 권역으로 나뉘고, 이 문서는 그중 **카리브·누에바에스파냐** 한 장을 다룹니다.

> 서인도 함대가 은을 싣고 떠나는 바다. 지협 하나가 두 대양을 가른다.

**항구 28곳 · 항로 41개 · 다른 바다로 나가는 길 5개**

## 0. ★ 가장 중요한 전제 — 이 지도는 실제 지리의 투영이 아닙니다

**이 프로젝트는 지도를 세 번 발주해 세 번 다 반려했습니다.** 사유가 매번 달랐고,
그 셋을 다 피하는 것이 이 문서의 목적입니다.

- **1차** — 실제 바다를 정확하게, 픽셀아트로서도 훌륭하게 그렸습니다. 그런데 게임에 얹으니
  **항구가 최대 55px 어긋나** 사막 한복판에 앉았습니다. 이 게임의 지도는 위경도를 옮긴 것이
  아니라 **플레이하기 좋게 늘리고 줄인 도식**이기 때문입니다.
- **2차** — 좌표에는 맞췄으나 **도시와 항로의 볼록껍질을 그냥 바다로 칠했습니다.**
  반도도 섬도 없어 지도로 읽히지 않았습니다. 검수 항목만 역설계한 그림이었습니다.
- **3차(AI 생성)** — 그림 자체는 훌륭했고 **기계 검수도 통과했습니다.** 그런데 게임 좌표를 얹으니
  베네치아·바르셀로나·나폴리·아테네·알렉산드리아가 **바다 한가운데** 떠 있었습니다
  (알렉산드리아는 뭍에서 64px = 화면 폭의 16%). 검수기가 그것을 못 잡던 것이라 검수를 고쳤습니다(§6).

> ### 작업 순서를 뒤집어 주세요
>
> ❌ 실제 지리를 그린다 → 도시를 얹는다
> ✅ **기준판 위에 덧그린다** — 해안선 실루엣은 그대로 두고 질감·명암·산·숲·수심만 얹습니다
>
> 지형은 "그 바다처럼 보이면" 됩니다. 실제 지리와 몇 도 어긋나는 것은 **문제가 아닙니다.**
> **항구가 물가에 있고 항로가 바다를 지나는 것이 훨씬 중요합니다.**

### 기준판 넉 장을 함께 드립니다 — 덧그리기가 유일하게 성립하는 방식입니다

| 파일 | 무엇 | 어떻게 쓰나 |
|---|---|---|
| `<권역>.png` | 지금 게임이 쓰는 지도 400×225 | 최종 규격 확인용 |
| **`<권역>-x4.png`** | 그것을 4배로 키운 1600×900 | **이 위에 덧그립니다** |
| **`<권역>-coast.png`** | 해안선만 남긴 흑백 판 | **지켜야 하는 실루엣.** 다 그린 뒤 겹쳐 대조하세요 |
| `<권역>.webp` | 같은 그림(참고용) | — |

납품은 **400×225 PNG 한 장**입니다. `<권역>.png`와 같은 이름으로 덮으면 그대로 게임에
들어갑니다 — 코드는 손대지 않습니다.

점·선·이름표가 어디 찍히는지 보시려면:

```
python serve.py 8155          # 프로젝트 루트에서
http://localhost:8155/mapcheck.html
```

- **[지형만 (발주용)]** 단추를 누르면 점·선·이름표가 빠진 순수 지형이 나옵니다.
- 배율 1×가 실제 크기(400×225)입니다. 2×·3×는 판독용입니다.
- 페이지 아래에 **검수 판정이 실시간으로** 뜹니다 — 납품본을 같은 자리에 넣으면 같은 판정을 받습니다.

## 1. 규격

| 항목 | 값 |
|---|---|
| 크기 | **400 × 225 픽셀** (정확히) |
| 비율 | **16:9 고정.** 게임 화면(논리 해상도)에 박혀 있어 바꿀 수 없습니다 |
| 크게 작업할 때 | **정수배만** — 800×450(2×) · 1200×675(3×) · **1600×900(4× · 기준판 `-x4`가 이 크기)** |
| 형식 | PNG (무손실). WebP로 낼 경우 **반드시 무손실**로 — 2차 납품이 손실 WebP라 48색이 10,862색으로 번졌습니다 |
| 색 수 | **256색 이하.** 기준판 자체가 130~257색입니다(바다 세로 그라데이션 때문). 다만 **디더링으로 만든 색**이어야 하고, 그라데이션·안티에일리어싱으로 번진 색은 안 됩니다 |
| 줄일 때 | 큰 판에서 400×225로 줄일 때는 **최근접 이웃(nearest neighbor)**. 바이리니어·란초스는 픽셀을 뭉갭니다 |
| 확대 | 게임에서 **정수배로만** 확대됩니다. 1px이 그대로 1px입니다 |

## 1-A. ★ AI로 그리신다면 — 비율이 가장 먼저 어긋납니다

AI 이미지 생성은 **비율부터 맞지 않습니다.** 여기서 막히면 뒤의 모든 것이 무의미해집니다.

**쓸 수 있는 크기는 셋뿐입니다** — 800×450 · 1200×675 · **1600×900**(권장, 기준판 `-x4`와 같은 크기).

| 흔한 AI 출력 | 400×225의 몇 배인가 | 왜 안 되나 |
|---|---|---|
| 1024×1024 (기본 정사각형) | — (비율 1:1) | 16:9가 아닙니다. **어떻게 잘라도 못 맞춥니다**(아래 실측) |
| 1024×576 | 2.56배 | 비율은 16:9지만 **정수배가 아닙니다.** 줄이면 픽셀 격자가 깨져 1px 선이 흐려집니다 |
| 1344×768 · 1920×1080 | 3.36배 · 4.8배 | 같은 이유 |
| **1600×900** | **4배** | ✅ 이것으로 주세요 |

### 정사각형으로 받은 것은 나중에 못 고칩니다 (다섯 경로를 다 시험했습니다)

3차 납품이 정확히 이 경우였고, 살려 보려고 다섯 가지를 전부 해봤습니다:

| 시도 | 결과 |
|---|---|
| ① 16:9로 자르기 | 동지중해가 화면 밖으로 나갔습니다 |
| ② 세로로 눌러 담기(3.73배) | 이탈리아 반도·아드리아해·에게해가 **소멸**했습니다 |
| ③ 레터박스(274×225 + 좌우 여백) | 왜곡 0으로 지형은 온전했으나 **항로 52개 중 18개가 반도를 관통**했습니다(제노바~나폴리 100%) |
| ④ 항구 좌표를 그림에 재배치 | 28곳 중 26곳은 앉았지만 **이스탄불이 어느 경유로도 안 닿았습니다** |
| ⑤ 육지를 3px 깎기 | 관통은 4개로 줄었으나 바다가 90%가 되어 검수 상한(80%)을 넘었습니다 |

**원인은 그림 실력이 아니라 축척입니다.** 400×225에서 1px이 10~15km인데 연안 항로는 5~20km라
**1~2px로 뭉개집니다.** 사실적인 해안선과 직선 항로 판정은 이 해상도에서 양립하지 않습니다 —
이 게임의 지도가 도식인 이유가 그것입니다.

### ⇒ AI를 쓰시려면 img2img로

- **text2img로 새로 뽑지 마세요.** `<권역>-x4.png`(1600×900)를 입력으로 넣고 **낮은 강도(denoise/strength)**로 질감만 얹습니다.
- 다 그린 뒤 **`-coast.png`를 겹쳐** 해안선이 밀리지 않았는지 봅니다. 실루엣이 바뀌면 그 시점에서 반려 사유가 됩니다.
- AI는 **글자·나침도·범례·항로선·배 아이콘을 스스로 그려 넣습니다.** 전부 금지입니다(§2-A) — 게임이 그 위에 같은 것을 다시 그려 두 번 겹칩니다.
- AI 출력은 **안티에일리어싱과 노이즈가 기본**입니다. 그대로 줄이면 색이 수천 개로 번집니다(2차 납품 48색 → 10,862색). 줄이기 전에 팔레트를 고정하고 최근접 이웃으로 축소하세요.
- 좌표를 프롬프트로 지정할 수는 없습니다. **§3 좌표표가 정본**이고, 그것을 만족하는 것은 덧그리기뿐입니다.

## 2. 톤 (프로젝트 공통 · 항구 배경 의뢰서와 같습니다)

- **2D 픽셀아트.** 고급스러울 필요는 없지만 **싸구려로 보이면 안 됩니다.**
- 위에서 내려다본 항해도입니다. 원근·그림자 없이 평면으로.
- 바다는 **어두운 쪽**, 육지는 **밝은 쪽**입니다. 그 위에 1px짜리 배 점과 항구 표식이 얹히므로
  **바다에 밝은 얼룩이 크게 들어가면 그 점들이 묻힙니다**(2차 납품에서 바다의 24%가 그랬습니다).
- 해안선은 백사장 → 얕은 물 → 깊은 물로 **서너 겹** 번지게. 지금 기준판이 그 방식입니다.

## 2-A. ★ 그리지 말아야 하는 것

게임이 코드로 그리는 것을 그림에 넣으면 **두 번 겹쳐 보입니다.** 다음은 넣지 마세요:

| 넣지 말 것 | 게임이 어떻게 그리나 |
|---|---|
| **도시 이름 글자** | DOM 오버레이로 그립니다(한글). 그림에 박히면 이름이 두 번 뜨고, 축소하면 뭉개집니다 |
| **항로선·점선** | §4의 데이터대로 그립니다. 그림의 선은 실제 항로와 무관해 거짓 정보가 됩니다 |
| **항구 점·별** | 도시 원을 §3의 좌표에 그립니다 |
| **배 아이콘** | 상인·해적이 살아 움직입니다. 배경에 박힌 배는 영원히 같은 자리에 멈춥니다 |
| **나침도·범례·테두리·격자** | 화면 UI는 DOM입니다 |

**지형만** 주세요 — 해안선·수심(얕은 바다 띠)·산·숲·사막·강.

## 6. 검수 — 납품 전에 직접 확인해 주세요

최종 판정은 저희가 `python tools/check-map.py --all`로 냅니다. 아래가 **그 검사 전부**이고,
하나라도 걸리면 반려입니다. `mapcheck.html`은 같은 기준을 브라우저에서 눈으로 대조하는 화면입니다.

| 항목 | 기준 | 왜 |
|---|---|---|
| 항구가 물가인가 | 각 점 반경 6px 안에 **바다와 뭍이 둘 다** 있을 것 | 뭍에 앉으면 배가 못 들어갑니다 |
| ★ **항구가 바다 한가운데 뜨지 않았나** | 가장 가까운 뭍까지 **28px 이내**. 기준판 아홉 장은 **평균 6.4px**입니다(권역별 5.1~7.3px) | **3차 반려 사유.** 이 검사가 없어서 그 그림이 통과했습니다 — "물이 닿는가"만 보면 바다 한복판은 늘 통과합니다 |
| ★ **지형이 좌표계와 같은가** | 뭍까지 12px을 넘는 항구가 **절반 미만**(기준판은 20% 안쪽) | 실제 지리대로 그린 그림은 이 게임의 도식 좌표와 맞지 않습니다. 하나둘이 아니라 절반이 뜨면 **다른 세계를 그린 것**입니다 |
| 항로가 바다를 지나는가 | 각 선분의 육지 비율 **34% 미만**(양끝 3px은 접안 구간이라 셈에서 뺍니다) | 배가 산을 넘습니다 |
| 육지/바다 비율 | 바다가 **20~80%** | 한쪽이 8할을 넘으면 지도로 안 읽힙니다 |
| 이름표 자리 | 이름표 상자가 남의 항구 표식을 덮지 않을 것 | 이름표는 항구 **위쪽**에 배경 박스째 그려집니다(한글 글자당 약 6px) |

섬 항구는 물에 둘러싸이는 것이 정상이며 실패로 세지 않습니다.

> ★ **기계 검수는 최소조건입니다.** 세 번의 반려 중 **두 번이 기계 검수를 통과했습니다**
> (2차는 검수 항목만 역설계한 그림, 3차는 위 두 검사가 없던 때). 그래서 저희는 판정과 별개로
> **좌표를 그림 위에 찍어 눈으로 대조**합니다. 보내시기 전에 `mapcheck.html`에서 같은 것을 해보세요.
