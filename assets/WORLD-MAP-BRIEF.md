## 0-A. ★ 가장 중요한 전제 — 이 지도는 실제 지중해의 투영이 아닙니다

**1차 납품이 이것 하나 때문에 반려됐습니다.** 1차 그림은 실제 지중해를 정확하게,
그리고 픽셀아트로서도 훌륭하게 그렸습니다. 그런데 게임에 얹으면 못 씁니다.

이 게임의 지도는 실제 위경도를 옮긴 지도가 **아니라** 도식(diagram)입니다.
플레이하기 좋게 동지중해를 넓게 펴고 서지중해를 줄여 놓았습니다. 실제 위경도로
최소제곱 맞춤을 해 보면 **도시가 최대 55px까지 어긋납니다**(화면 폭의 14%).
크롭·확대·회전 어떤 변환으로도 맞출 수 없는 크기입니다. 예를 들어

- 실제 로도스와 알렉산드리아는 경도가 거의 같지만(28.2°E / 29.9°E), 게임에서는 x가 **239 / 320**입니다
- 실제 튀니스는 시칠리아 서쪽인데, 게임에서는 팔레르모보다 **동쪽**(x 174 vs 151)입니다

**그래서 지리를 정확히 그릴수록 게임에서는 더 틀립니다.**

> ### 작업 순서를 뒤집어 주세요
>
> ❌ 실제 지중해를 그린다 → 도시를 얹는다
> ✅ **첨부한 기준판의 점 16개를 먼저 놓는다 → 그 점들이 물가에 오도록 지형을 그린다**
>
> 첨부 파일 (`assets/map-reference/`):
>
> | 파일 | 무엇 |
> |---|---|
> | `coord-target.png` | 400×225 원본 크기. **마젠타 1px 점이 항구 정위치**이고 회색 선이 항로입니다. 이 위에 레이어를 얹어 작업하세요 (지중해 기준판이며, 권역별 판은 `map-briefs/<권역>-coast.png`) |
> | `coord-target-4x.png` | 4배 확대 판독용. 도시 이름·좌표와, 이름표가 덮는 영역(주황 사각)이 표시돼 있습니다 |
> | `rejected-overlay.png` | 1차 납품 그림 위에 게임 좌표를 얹은 것. **무엇이 문제였는지 한 장으로 보입니다** |
>
> 지형은 "지중해처럼 보이면" 됩니다. 실제 지리와 몇 도 어긋나는 것은 **문제가 아닙니다.**
> 항구가 물가에 있고 항로가 바다를 지나는 것이 **훨씬 중요합니다.**

### 1차 납품 검수 결과 (반려 사유)

`python tools/check-map.py assets/map/mediterranean.webp` 실측입니다.

| 항목 | 결과 |
|---|---|

지리가 아니다"라는 말이 없었습니다. 그 경고와 기준판을 §0-A에 추가한 것이 이번 개정입니다.

## 1. 지금 무엇이 잘못됐나 — 실측

현재 지도는 100×56 저해상 격자에 바다 구간을 적고 4배로 키운 뒤 경계를 스무딩합니다.
섬은 그 위에 타원으로 따로 찍습니다. 그 결과 섬끼리의 간격이 실제 지리와 어긋납니다.

섬 사이 최단 거리를 재 봤습니다(단위 px, 축척은 대략 **10km/px**):

| 섬 쌍 | 지도상 간격 | 실제 거리 | 판정 |
|---|---|---|---|
| 시칠리아 ~ 몰타 | **0px (맞붙음)** | 약 90km (≈9px) | **오류** — 한 덩어리로 보였음 |
| 사르데냐 ~ 코르시카 | 1px | 약 11km (≈1px) | 맞음 (보니파초 해협은 실제로 매우 좁다) |

시칠리아~몰타는 이번에 **9px 떨어뜨려 고쳤습니다.** 다만 이건 발견한 한 건일 뿐이고,
아래 문제들은 코드로 못 고칩니다 — **그림으로 다시 그려야 하는 것들**입니다.

### 코드로는 해결이 안 되는 것

1. **해안선이 스무딩으로 뭉개집니다.** 격자를 4배로 키우고 경계를 부드럽게 만드는 방식이라
   좁은 만·곶·삼각주 같은 **작은 지형이 살아남지 못합니다.** 아드리아해 동안의 달마티아
   해안(수백 개의 좁고 긴 섬)은 지금 그냥 매끈한 선입니다.
2. **섬이 전부 타원입니다.** 시칠리아는 삼각형, 사르데냐는 세로로 긴 사각형, 크레타는
   가로로 긴 막대인데 지금은 다 같은 타원입니다. 실루엣만으로 어느 섬인지 알 수 없습니다.
3. **반도의 특징이 없습니다.** 이탈리아 반도의 장화 모양, 그리스의 펠로폰네소스,
   아나톨리아의 돌출 — 이것들이 지중해 지도를 "지중해처럼" 보이게 하는 형태인데
   격자 방식으로는 이 정도 해상도가 안 나옵니다.
4. **수심·지형 표현이 없습니다.** 바다가 단색에 가깝고 육지도 평평합니다.

## 2. 필수 규격

| 항목 | 값 |
|---|---|
| 해상도 | **정확히 400 × 225 px** |
| 포맷 | **WebP — 반드시 무손실(lossless).** quality 90도 안 됩니다(1차 반려 사유) |
| 알파 | **불투명** |
| 안티에일리어싱 | **금지** |
| 스케일링 | **금지** — 작게 그려 확대하지 마세요 |
| 파일 크기 | **80KB 이하** |

### WebP 무손실로 저장하는 법

손실 WebP는 픽셀아트에서 **안티에일리어싱을 다시 넣는 것과 같습니다.** 1차 납품은
48색으로 잘 양자화해 놓고 손실 WebP로 저장하는 바람에 10,862색으로 번져 반려됐습니다.
게임은 이 그림을 4배로 확대하므로 번진 가장자리가 그대로 4배가 됩니다.

```bash
cwebp -lossless -z 9 map.png -o mediterranean.webp     # cwebp
# 또는 Pillow:  im.save('mediterranean.webp', lossless=True, quality=100, method=6)
```

저장 후 **색 수가 48색 이하로 유지됐는지** 반드시 확인하세요(§8의 검사 스크립트가 봅니다).
PNG 원본도 함께 주시면 대조할 수 있어 좋습니다.

### 안티에일리어싱 금지 (항구 배경과 동일)

게임은 이 그림을 **정수배로 확대**합니다(400×225 → 1600×900 등). 보간을 끄기 때문에
(`imageSmoothingEnabled = false`) 흐린 가장자리는 흐린 채로 4배가 됩니다.

- 반투명 픽셀·소프트 브러시·부드러운 그라데이션 금지
- **해안선은 1px 단색 선**으로 또렷하게. 이것이 이 그림에서 가장 중요한 선입니다
- 바다 깊이는 그라데이션이 아니라 **색 띠 3~4단계**로 계단지게

### ⚠️ 생성형 AI로 만들 때 (항구 배경과 동일)

이미지 생성 모델은 진짜 픽셀 그리드를 못 만듭니다. 반드시:

1. 크게 생성 (예: 1600×900)
2. **최근접 이웃(nearest neighbor)** 으로 400×225 축소 — bilinear/bicubic 금지
3. **48색 이하로 양자화**, 디더링 끄기 (지도는 항구 배경보다 색이 적어야 합니다)
4. 400×225에서 **해안선을 1픽셀 단위로 손보정** — 이 지도는 해안선이 전부입니다
5. WebP 저장

> **지도는 항구 배경보다 AI 생성이 더 위험합니다.** 지리를 틀리기 때문입니다.
> 생성 모델은 그럴듯한 해안선을 만들지만 실제 지중해가 아닙니다.
> **실제 지중해 윤곽을 먼저 확보하고(공개 도메인 지도 참고), 그 위에 픽셀로 옮기는**
> 순서를 권합니다. "지중해처럼 생긴 것"이 아니라 "지중해"여야 합니다.

## 4. 지리 — 반드시 들어가야 하는 형태

이 지도가 지중해로 읽히려면 아래 형태들이 살아 있어야 합니다.
**작은 지형을 살리는 것이 이번 의뢰의 핵심**입니다.

> ⚠️ **단, §0-A가 이 절보다 우선합니다.** 아래 좌표는 "대략 이 근처"라는 뜻이고,
> 실제 지리와 충돌하면 **기준판의 도시 점을 따르세요.** 지형이 실제 지중해와
> 조금 달라지는 것은 허용되지만, 항구가 물가에서 벗어나는 것은 허용되지 않습니다.
> 화면 전체가 지중해입니다 — 북유럽·사하라 같은 **지중해 밖 대륙으로 화면을 채우지 마세요.**
> 육지는 화면의 **절반을 넘지 않아야** 합니다(1차 납품은 70%였습니다).

### 반도 (실루엣으로 즉시 알아볼 수 있어야)

- **이탈리아 반도** — 장화 모양. 발끝(칼라브리아)과 뒤꿈치(풀리아)가 갈라져야 합니다
- **이베리아 반도** — 서쪽 끝. 지브롤터 해협이 좁게 열려 있어야 합니다
- **그리스** — 펠로폰네소스가 거의 섬처럼 잘록하게 매달림. 서안이 톱니처럼 들쭉날쭉
- **아나톨리아** — 동쪽으로 뻗은 넓은 육괴. 남안이 완만하게 활처럼
- **북아프리카** — 남쪽 경계. 시르테만이 안쪽으로 크게 파여야 합니다

### 섬 — 각각 다른 실루엣

| 섬 | 형태 | 대략 위치 (x, y) |
|---|---|---|
| 시칠리아 | **삼각형** (트리나크리아) | 156, 147 |
| 사르데냐 | 세로로 긴 사각형 | 119, 110 |
| 코르시카 | 세로로 긴 삼각형, 사르데냐 바로 위 **1px 해협** | 117, 90 |
| 크레타 | 가로로 아주 긴 막대 | 225, 135 |
| 키프로스 | 가로로 긴, 동쪽 끝이 뾰족 | 329, 111 |
| 발레아레스 | 작은 섬 3개 무리 | 85, 111 |
| 로도스 | 작은 타원 | 239, 109 |
| **몰타** | 아주 작은 점. **시칠리아에서 9px 이상 떨어져야** | 169, 161 |
| 에게 제도 | 작은 점 여러 개가 흩뿌려짐 | 209~232, 84~100 |
| 이오니아 제도 | 그리스 서안에 붙은 작은 섬들 | 188~196, 108~121 |

> **가장 자주 나는 실수: 시칠리아~몰타, 사르데냐~코르시카를 붙여 버리는 것.**
> 사르데냐~코르시카는 실제로 1px만큼 가까운 것이 맞습니다(보니파초 해협).
> 하지만 **붙으면 안 됩니다** — 1px이라도 바다색이 지나가야 합니다.
> 몰타는 시칠리아에서 확실히 떨어져야 합니다.

## 5. 도시 위치 — 이 16점이 이 그림의 설계도입니다

점과 이름표가 여기에 찍힙니다. 각 좌표는 **육지 가장자리(해안선 위)** 여야 합니다 —
정확히는 그 픽셀 주변 5×5 안에 **육지와 바다가 모두** 있어야 합니다(검사 스크립트 기준).

기준판 `assets/map-reference/coord-target.png`에 이 16점이 마젠타 1px로 찍혀 있습니다.
숫자를 옮겨 적지 말고 **그 파일을 레이어로 깔고 작업하세요.**

| 도시 | x, y | | 도시 | x, y |
|---|---|---|---|---|
| 베네치아 | 141, 63 | | 이스탄불 | 241, 55 |
| 제노바 | 116, 76 | | 부르사 | 222, 66 |
| 마르세유 | 91, 71 | | 이즈니크 | 242, 76 |
| 바르셀로나 | 57, 89 | | 아테네 | 191, 110 |
| 나폴리 | 131, 110 | | 로도스 | 239, 109 |
| 팔레르모 | 151, 144 | | 베이루트 | 351, 121 |
| 튀니스 | 174, 157 | | 알렉산드리아 | 320, 159 |
| 알제 | 106, 151 | | **몰타** | **169, 161** |

주의할 점:

- **이스탄불·부르사·이즈니크 세 곳이 가장 붐빕니다** (x 222~242, y 55~76).
  이 구역은 지형을 특히 단순하게 두세요 — 이름표 3개가 겹칠 자리입니다
- **부르사·이즈니크는 실제로는 내륙**입니다. 게임 편의상 항구로 다루므로
  마르마라해 남안과 이즈니크 호수가 보이면 자연스럽습니다
- 몰타는 **섬 위에 점 하나**입니다. 섬이 너무 작으면 점에 가려 사라지니 3~4px은 되게

## 6. 색 — 게임 팔레트

항구 배경과 같은 팔레트를 씁니다. 다만 지도는 **색을 더 적게** 쓰세요.

```
바다      #0e2a40 (깊은 바다) / #1b5570 (기본) / #3f93ab (연안 얕은 물)
육지      #26432a (짙은 산지) / #456f39 (기본 육지) / #79a44f (마른 평지)
사막·남안  #8a6a44 / #c2a06a / #e6cd9a
해안선     #17121c (먹색 1px) 또는 육지색의 가장 어두운 톤
```

- 바다는 **3단계**면 충분합니다: 깊은 바다 / 기본 / 연안
- 육지는 북쪽(유럽)을 초록 계열, 남쪽(아프리카·레반트)을 황토 계열로 나누면
  지도만 봐도 기후대가 읽힙니다
- **채도 높은 색 금지.** 이 지도 위에 붉은 점(해적)과 흰 점(상인)이 찍히므로,
  배경에 붉거나 흰 것이 있으면 안 됩니다

## 7. 넣지 말아야 할 것

- **국경선** — 이 시대에 선으로 그은 국경은 없고, 게임에서도 깃발로 표현합니다
- **도시 이름 텍스트** — 게임이 직접 그립니다. 그림에 글자를 넣으면 이중으로 겹칩니다
- **항로 선** — 게임이 점선으로 그립니다
- **나침도·괘선·장식 테두리** — 공간이 없습니다(400×225에 도시 16곳이 들어갑니다)
- **양피지 질감·얼룩** — 1px 점들이 묻힙니다. 낡은 해도 느낌은 매력적이지만
  이 해상도에서는 가독성을 죽입니다

## 8. 검수 기준

### 먼저 기계 검사를 통과시켜 주세요

납품 전에 이 한 줄을 돌리면 아래 1~6번이 자동으로 판정됩니다. **반려 0건이어야 합니다.**

```bash
python tools/check-map.py <납품파일.webp>      # 의존: pip install pillow
```

검사 항목: 규격 400×225 · 고유색 48 이하(손실 WebP 탐지) · 육지 비율 · **도시 16곳이
해안선 위인가** · **항로 28개가 바다를 지나는가** · 바다의 국소 대비(1px 점 가시성).
좌표는 게임 코드(`js/map/geo.js`)에서 직접 읽으므로 이 문서와 어긋날 일이 없습니다.

### 사람이 보는 기준

1. **400×225인가**
2. **100% 배율에서 픽셀이 또렷한가** — 흐린 해안선이 있으면 반려
3. **6개 해협이 전부 열려 있는가** — 하나라도 막히면 반려
4. **시칠리아~몰타, 사르데냐~코르시카가 붙지 않았는가**
5. **도시 16곳 자리가 전부 해안선 위인가** — 육지 한복판이나 바다 한복판이면 안 됩니다
6. **1px 흰 점과 붉은 점을 바다 아무 데나 찍었을 때 보이는가** — 안 보이면 바다가 시끄러운 것
7. **실루엣만으로 지중해로 읽히는가**

특히 5번은 좌표를 직접 찍어 확인해 주세요. 도시가 바다에 떠 있거나 내륙에 박히면
게임에서 항구 점이 엉뚱한 데 찍힙니다.
