## 3. 공통으로 지켜야 하는 것

| 항목 | 값 |
|---|---|
| 캔버스 | **400 × 225 px** (게임의 논리 해상도. 정수배로만 확대된다) |
| 비율 | **16:9 고정.** 화면에 박혀 있어 바꿀 수 없다 — 정사각형으로 받으면 살릴 방법이 없다(§4-C) |
| 크게 작업할 때 | **정수배만** — 800×450 · 1200×675 · **1600×900**(기준판 `-x4`) |
| 형식 | 지도 PNG · 배경 WebP (각 의뢰서에 명시) |
| 줄일 때 | **최근접 이웃(nearest)**. 바이리니어·란초스는 픽셀을 뭉갠다 |
| 안티에일리어싱 | **금지** — 확대하면 뭉갠 것처럼 보인다 |
| 시대 | **"대항해시대쯤"** — 특정 연도에 맞추지 않는다 |
| 좌표 | 지도는 **도시가 반드시 물가에 오도록** 정해진 좌표를 지킨다(각 의뢰서의 좌표표) |

## 4. 납품하면 어디에 꽂히나

- **권역 지도** → `assets/map/<권역>.png`로 덮으면 그대로 적용(판 번호가 붙어 새로고침으로 갈린다).
  좌표를 옮겼다면 `node tools/gen-map-png.mjs`를 먼저 돌린다.
  검수는 `python tools/check-map.py --all` — 항구가 뭍에 앉거나 **바다 한가운데 뜨면** 여기서 걸린다.
- **항구 배경** → `assets/manifest.json`에 `bake` 키를 적으면 **그 키만** 대체된다.
  키 목록은 `preview.html`에서 눈으로 확인한다. 절차는 [README.md](README.md).

### 4-A. ★ 그리지 말아야 하는 것 (지중해 3차에서 실제로 겪음)

게임이 코드로 그리는 것을 그림에 넣으면 **두 번 겹쳐 보입니다.** 다음은 넣지 마세요:

| 넣지 말 것 | 게임이 어떻게 그리나 |
|---|---|
| **도시 이름 글자** | DOM 오버레이로 그립니다(한글). 그림에 박히면 이름이 두 번 뜨고, 축소하면 뭉개집니다 |
| **항로선·점선** | `ROUTES` 데이터대로 그립니다. 그림의 선은 실제 항로와 무관해 거짓 정보가 됩니다 |
| **항구 점·별** | 도시 원을 좌표에 그립니다 |
| **배 아이콘** | 상인·해적이 살아 움직입니다. 배경에 박힌 배는 영원히 같은 자리에 멈춥니다 |
| **나침도·범례·테두리** | 화면 UI는 DOM입니다 |

**지형만** 주세요 — 해안선·수심(얕은 바다 띠)·산·숲·사막·강. 규격은 **400×225**이고,
크게 그려야 한다면 **정수배(800×450 · 1600×900)**로 주세요.

### 4-B. ★★ 가장 중요한 것 — 좌표가 지형을 정합니다 (3차 반려 사유)

이 게임의 지도는 **실제 지중해의 투영이 아니라 도식**입니다. 도시 좌표를 실제 위경도에 맞춰 보면
최대 55px(화면 폭의 14%) 어긋납니다 — 로도스와 알렉산드리아는 실제 경도가 거의 같은데 게임에선
x가 239와 320이고, 튀니스는 실제로 시칠리아 서쪽인데 게임에선 팔레르모보다 동쪽입니다.

**그래서 진짜 지리대로 그린 그림일수록 게임에서는 더 틀립니다.** 3차 납품은 지중해를 훌륭하게
그렸지만, 게임 좌표를 얹으니 베네치아·바르셀로나·나폴리·아테네·알렉산드리아가 **바다 한가운데**
떠 있었습니다(알렉산드리아는 뭍에서 64px). 정사각형으로 온 것을 어떻게 잘라도 맞지 않았습니다 —
**자르기로 해결되는 문제가 아닙니다.**

⇒ **`<권역>-x4.png` 위에 덧그려 주세요.** 해안선 실루엣(`-coast.png`)은 그대로 두고
질감·명암·산·숲·수심만 얹습니다. 좌표표의 도시가 **뭍과 물이 만나는 자리**에 오는 것이
합격 조건입니다(기준판 아홉 장은 도시에서 뭍까지 평균 6.4px, 가장 먼 권역도 7.3px입니다).

**왜 실루엣을 못 바꾸나** — 3차 납품으로 다섯 가지를 다 시험했습니다: 16:9로 자르기(동지중해 손실),
세로로 눌러 담기(이탈리아 반도·아드리아해 소멸), 좌우 여백 채우기(지형은 온전했으나
**항로 52개 중 18개가 반도를 관통**), 항구 좌표 재배치(이스탄불이 어느 경유로도 안 닿음),
육지를 뒤로 물리기(항로는 열리지만 바다가 90%가 되어 지도가 아니게 됨).
원인은 **축척**입니다 — 400×225에서 1px이 10~15km라 연안 항로(5~20km)가 1~2px로 뭉개져
사실적 해안선과 직선 항로가 양립하지 않습니다. 게임 지도가 도식인 이유가 이것입니다.

이미 UI가 그려진 그림이 왔다면 `python tools/clean-map-art.py <입력> <권역> --scan`으로
지우고 크롭 후보를 훑을 수 있습니다(지형이 어긋난 것은 이것으로도 못 고칩니다).

### 4-C. ★ AI로 그리는 경우 — 비율에서 먼저 막힌다

3차 납품이 AI 생성이었고, **그림이 아니라 규격에서 무너졌다.** 흔한 AI 출력은 어느 것도 쓸 수 없다:

| AI 출력 | 400×225의 몇 배 | 왜 안 되나 |
|---|---|---|
| 1024×1024 (기본) | — (1:1) | 16:9가 아니다. 자르기·누르기·레터박스 **다섯 경로를 다 시험했고 전부 실패**(§4-B) |
| 1024×576 · 1344×768 · 1920×1080 | 2.56 · 3.36 · 4.8배 | 비율은 맞아도 **정수배가 아니라** 축소에서 픽셀 격자가 깨진다 |
| **1600×900** | **4배** | ✅ 기준판 `-x4.png`와 같은 크기 |

⇒ **text2img로 새로 뽑지 말고 `-x4.png`를 입력으로 img2img**, 낮은 강도로 질감만 얹는다.
AI는 글자·나침도·항로선을 스스로 그려 넣고(§4-A 위반) 안티에일리어싱이 기본이라
그대로 줄이면 색이 수천으로 번진다(2차 납품 48색 → 10,862색).
**자세한 것은 권역 의뢰서 §1-A**에 표와 실측으로 들어 있다.

## 5. 의뢰서를 고치지 마세요

`map-briefs/*.md`는 **생성물**입니다. 내용이 틀렸다면 게임 데이터(`js/regions/<권역>/geo.js`)를 고치고
`node tools/gen-map-brief.mjs`를 다시 돌립니다. 손으로 고치면 다음 생성 때 지워지고,
무엇보다 **의뢰서와 게임이 어긋납니다** — 지도 외주를 세 번 반려했고 1·2차의 원인이 정확히 그것이었습니다
(1차는 좌표를 옮겨 적다 틀렸고, 2차는 그 사이 도시가 늘었는데 의뢰서가 낡았습니다).
3차는 의뢰서가 맞았는데 **AI가 정사각형으로 뽑아 비율부터 어긋났습니다**(§4-C).
